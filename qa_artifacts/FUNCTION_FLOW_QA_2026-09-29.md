## 수정한 기능 결함

- 데이터 분할의 실제 저장값, 이미지 필터, 학습 입력이 다르게 해석될 수 있던 문제를 바로잡았다. 테스트 분할이 검증에 섞이지 않도록 하고, 로컬 LabelMe 링크 경로도 같은 분할로 매핑한다.
- 링크된 LabelMe 폴더를 앱 재시작 후 다시 열면 저장된 분할이 0/0/0으로 보이던 문제를 수정했다. 구조화된 마스크 데이터는 비활성 재분할 화면의 예상 수치 대신 원본의 실제 40/10/0 분할을 보여준다.
- 구조화된 분할·검출 데이터의 갤러리가 잘못된 파일을 선택하거나 마스크를 이미지로 노출하던 문제를 수정했다. 이상탐지의 `val/` 폴더가 없어도 학습 로더가 만든 결정적 검증 분할을 갤러리에서도 표시한다.
- 라벨링 이미지 로드 실패 시 빈 주석을 덮어쓸 수 있던 경로와, 같은 파일명에 서로 다른 경로가 있을 때 잘못된 이미지를 여는 경로를 차단했다.
- 브러시 마스크에 경계 상자가 없는데 검사기에서 `0×0 px`, `0 px²`로 표시하던 문구를 제거하고 픽셀 면적 미계측을 명시했다.
- 취소 요청 후 작업 종료를 확인할 때까지 상태를 추적하고, 중단된 작업과 새 학습이 겹치지 않도록 했다.
- 평가 리포트가 현재 완료 모델을 참조하도록 하고, 결과가 없을 때 리포트 버튼과 수치를 올바르게 제한했다.
- 5단계에서는 현재 데이터·완료 모델을 확인하기 전 저장·실행·복원을 막고, 이전 데이터의 늦게 도착한 결과가 새 화면에 남지 않게 했다. 플로우 이미지 선택도 전체 경로와 작업 유형을 기준으로 한다. 두 번째 고정 템플릿인 검출→ROI→검사를 노출하고, 저장본의 두 모델 ID를 지우지 않은 채 각 출처·작업 유형을 검증한다. 검출 모델이 빠진 5노드 템플릿은 저장·실행을 비활성화하고, 누락된 모델 종류를 화면에 구체적으로 안내한다.
- 6단계의 내보내기 범위를 실제 제공하는 Python 실행기로 정리하고 설치 목록을 포함했다. 평균 계산 시간이 목표 안에 있어도 P95 조건으로 실패하는 경우, 실패 사유를 P95로 정확히 표시하도록 수정했다.

## 남은 기능 범위

1. 현재 5단계 엔진은 **두 개의 고정된 직선형 템플릿**을 지원한다. Workflow가 설명하는 다중 모델 설계와 비교하면 임의 노드 추가·삭제, 연결 편집, 분기는 아직 없다. 두 모델 저장→재열기→출처 검증은 API 회귀 시험으로 확인했지만 이 NG LabelMe 데이터에 검출 체크포인트가 없어 실제 검출→ROI→검사 실행은 검증하지 않았다.
2. 지우개 제스처, 모든 줌·레이아웃 컨트롤, 모든 작업 유형의 실데이터 학습을 패키징 앱에서 하나씩 클릭한 것은 아니다. 관련 경로는 회귀 테스트와 코드 점검으로 확인했고, 실제 데이터 종단 시험은 분할 작업 중심이다.
3. 이 폴더에는 정상(OK) 샘플이 없으므로 과검률, OK/NG 임계값, 현장 품질은 검증할 수 없다. 시험 분할 1건에서 생긴 미검은 모델 품질 문제가 실제로 남아 있음을 보여준다.
4. 6단계의 패키지는 학습 모델 단독 추론을 제공한다. 5단계 플로우 전체의 그래프, ROI 체인, PLC 연계, 설비 PC의 입출력 시간은 내보내지 않는다.
