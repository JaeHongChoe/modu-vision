# 실제 데이터 기능·플로우 QA (2026-09-29)

이 문서는 이전 버전의 앱에서 수행한 역사적 QA 기록이다. 이후 5단계 편집 그래프와 6단계 저장 이력이 추가되었으므로 현재 상태는 [기능 비교표](../docs/NEUROT_PARITY_MATRIX_2026-09-29.md)와 [후속 QA](../docs/QA_NEUROT_PARITY_2026-09-30.md)를 참고한다. 고객 원본 경로, 이미지 파일명, 모델 작업 ID와 해시는 Git 밖의 상세 영수증에 보관한다.

## 확인한 범위

- 고객 제공 이미지 88장 중 80장에 LabelMe 라벨이 있었고 8장은 미라벨이었다. 171개 원본 파일의 SHA-256은 QA 전후 동일했다.
- 격리된 8쌍 복사/링크 데이터로 학습 6장·검증 1장·시험 1장의 분할을 저장하고 앱 재시작 후 재열었다. 원본 전체 폴더에서도 학습 중단 요청이 `ABORTED`로 마무리되고 시작 버튼이 다시 활성화됐다.
- 라벨링 복사본의 브러시·저장·재열기, 완료 모델의 평가/리포트, 원본→분할 검사→판정→출력의 4노드 플로우를 실제 이미지에 실행했다. 검사 결과는 OK였지만 NG 주석과 달라 모델 품질 문제를 확인했다.
- 검사 플로우를 저장·재열고 임계값 변경을 되돌렸다. 당시 검출 ROI 플로우는 체크포인트가 없어 템플릿만 확인했다. ONNX 패키지 자체 시험과 실제 이미지 crop 추론, 합성 입력 벤치마크도 확인했다.

## 당시 수정한 결함

- 분할 저장값·갤러리 필터·학습 입력 불일치, 재시작 후 분할 소실, 구조화 데이터의 잘못된 이미지 선택을 수정했다.
- 라벨 로드 실패 시 빈 주석 덮어쓰기, 동일 파일명 다른 경로의 이미지 혼동, 저장된 마스크 재열기 문제를 수정했다.
- 학습 취소 후 워커 종료 추적과 중복 작업 방지, 모델 없는 평가 리포트/플로우/내보내기 차단을 추가했다.
- 플로우의 출처·작업 유형·완료 체크포인트 확인, ROI 모델 누락 안내, 실제 제공하는 단독 Python 내보내기 설명을 정리했다.

## 당시 검증과 한계

당시 백엔드 전체 회귀는 407 passed, 2 skipped, 프런트 스크립트는 101 passed, 0 failed였다. TypeScript와 Vite 빌드, 격리된 macOS 앱 패키징도 완료했다. 이 숫자는 현재 빌드의 최종 회귀 수치가 아니다.

NG 중심 데이터만으로 정상 제품 과검률이나 양산 승인 수준의 판정을 검증할 수 없다. 벤치마크는 합성 입력의 모델 계산 시간이다. 이 시점의 플로우는 두 고정 템플릿만 지원했으며, 이후 편집 가능한 제한된 DAG로 확장되었다. 최신 범위와 제한은 후속 문서를 따른다.
