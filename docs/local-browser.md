# 이 PC에서 브라우저로 Studio 실행하기

소스를 설치한 PC에서 `npm run web`을 실행하고 `https://localhost:8443`으로
접속합니다. Python 엔진이 이 PC에서 계산하고, 웹 전용 폴더에 계정·프로젝트·작업을
저장합니다. 화면 없이 실행되는 Electron 보조 프로그램이 폴더 창·파일 열기·도우미의
OS 보호 저장소를 담당합니다. LAN·외부 호스팅용 실행기가 아닙니다.

## 준비와 실행

[README의 개발 환경 설치](../README.md#빠른-시작)를 먼저 완료하세요.
Node.js 24, Python 3.13, `npm ci`로 설치한 Electron·TypeScript·renderer 의존성과 기존 Python requirements가
필요합니다. 실행기는 패키지를 설치하거나 모델을 내려받지 않습니다.
저장소 루트 터미널에서 실행합니다.

macOS에서 기존 가상환경을 선택하는 예:

```bash
export VISION_AI_PYTHON="$PWD/.venv/bin/python"
npm run web
```

`.venv` 또는 `venv`가 저장소에 있으면 자동으로 선택하므로 환경변수는 생략할 수
있습니다. 지정 값은 **Python 실행파일 경로 하나**입니다. 옵션이 붙은 명령문을
넣지 마세요. 가상환경이 없으면 macOS/Linux는 `python3`, Windows는 `python`을 찾습니다.

Linux의 명령 형식은 다음과 같습니다. 이 브라우저 실행기의 Linux 런타임은 아직
검증하지 않았습니다.

```bash
export VISION_AI_PYTHON="$PWD/.venv/bin/python"
npm run web -- --no-open
```

Windows PowerShell의 선택·도움말 명령 형식입니다.
**현재 Windows 서버 실행은 지원하지 않습니다.** 개인 키의 Windows ACL 비공개성을
검사하기 전까지 TLS 단계에서 명시적으로 중단합니다. 이 명령 예는 Windows 실행
검증이나 지원을 뜻하지 않습니다.

```powershell
$env:VISION_AI_PYTHON = "$PWD\.venv\Scripts\python.exe"
npm run web -- --help
```

2026-10-26 macOS의 기존 웹 경로에서 실제 제품 실행기와 격리 Chromium으로 로그인·프로젝트 생성·ZIP
업로드·라벨 저장·분할, 합성 이미지 16장의 CPU 학습 1회와 저장 모델 평가, 같은 포트의
WSS 재연결·새 로그인 후 저장 결과를 확인했습니다. [검증 근거](verification/2026-10-26-local-browser.md)를
참고하세요. 합성 데이터 기능 검증이며, 모델 품질·현장 수락·설치형 패키지나 다른 OS의
검증을 뜻하지 않습니다.

2026-10-27에 추가한 보조 프로그램·폴더 선택·복원·도우미·원격 연결은 구현과
개별 검토를 마쳤고 통합 검증 중입니다. 최신 제품 소스와 도우미 fixture를 담은
`e88f1b3b` 기준으로 renderer/main 2,499개, 웹·보조 프로그램·복원 352개,
E2E 하네스 67개가 통과했습니다. 별도 opt-in Electron 검사는 전체 Node 실행의
1개 skip과 구분하며, 실제 컴파일 진입점의 별도 통과 기록도 보존합니다.

사용자가 인증서와 네이티브 기능 허용을 직접 확인한 뒤 실제 브라우저의 40장 폴더
선택·취소·클래스 저장·재접속, LabelMe·COCO·YOLO·픽셀 마스크 교환과 보고서 다운로드를
확인했습니다. 마스크 복원 경로와 복원본 재로그인의 등록키/프로젝트 ID 구분 문제를
재현·수정하고 독립 검사를 마쳤습니다. 도우미는 실제 브라우저/보조 프로그램 경로에
모의 공급자를 연결해 읽기·확인 후 1회 쓰기·취소·로그·계정/탭 격리를 검증했습니다.
실제 공급자 로그인이나 유료 호출·이미지 전송은 하지 않았습니다.

최신 수정 후 새 위치의 실제 마스크 재복원은 남아 있습니다. 검증 브라우저 도구가
설정상 플러그인이 켜져 있음에도 로컬 브라우저 비활성 응답을 반환해 해당 UI 작업을
중단한 상태입니다. 설치된 사용자 앱이나 기본 웹 8443의 설정 문제로 확인된 것은
아닙니다. 최신 head의 CI와 이 실제 화면 확인을 마치기 전에는 앱과의 전체 기능 일치
수락이나 병합 완료로 판단하지 마세요.
[현재 통합 검증 기록](verification/2026-10-27-local-web-desktop-parity.md)을 참고하세요.

처음에는 터미널에서 관리자 이름, 비밀번호, 비밀번호 확인을 입력합니다.
이름은 영문·숫자·`_ . @ -`로 3~80자, 비밀번호는 12~1024자입니다.
비밀번호 입력은 화면에 표시되지 않습니다. 숨김 입력을 사용할 수 없으면 계정을
만들지 않습니다. 계정은 기존 AccountStore의 암호 해시로 저장됩니다.
이미 계정이 있으면 다시 생성하지 않습니다.

터미널 입력이 없는 첫 실행은 거절됩니다. 같은 데이터 폴더를 지정해 일반 터미널에서
다음 명령을 한 번 실행하고 계정을 설정하세요. 브라우저에는 최초 관리자 생성 기능이
노출되지 않습니다.

```bash
npm run web -- --data-dir "/absolute/path/to/modu-web-data"
```

실행할 때마다 현재 소스의 renderer와 보조 프로그램을 해당 데이터 폴더의
`renderer/`, `native-helper/`에 빌드합니다. 보조 프로그램은 전용 `native-host/` 상태와
비공개 표준 입출력으로 연결됩니다. 준비 응답과 실제 왕복이 확인된 뒤 서버를 엽니다.
이 폴더는 실행기 전용이며 다시 빌드할 때 비워집니다. 기존 문서·소스를 넣지 마세요.
동일 데이터 폴더의 잠금을 먼저 확보하므로 중복 실행이 활성 서버의 화면 파일을
다시 만들지 않습니다. 데이터 폴더가 다르면 빌드 결과도 분리됩니다.
빌드 실패 시 서버를 시작하지 않습니다.

## 주소와 옵션

```bash
npm run web -- --port 8444 --no-open
python -m backend.web --data-dir "/absolute/path/to/modu-web-data" --port 0 --no-open
npm run web -- --help
```

두 번째 명령의 `python`은 의존성이 설치된 인터프리터를 사용하세요. 기본 포트는
8443이며 `--port 0`은 OS가 빈 포트를 선택합니다. 실제 주소는 준비 출력으로 확인합니다.
바인딩은 항상 `127.0.0.1`입니다. 브라우저 주소는 정확히 `https://localhost:포트`를
사용하세요. 다른 Host·Origin, HTTP, 위조 전달 헤더로 경계를 우회할 수 없습니다.
`--help`는 데이터 생성·빌드·서버 실행을 하지 않습니다.

실제 HTTPS `/health` 확인과 인증서 검증이 끝나면 다음 형태의 한 줄을 출력한 뒤
기본 브라우저를 엽니다. `--no-open`은 자동 열기만 끕니다.

```text
MODU_WEB_READY={"url":"https://localhost:8443","pid":12345,"data_dir":"...","certificate_file":".../tls/localhost-cert.pem","certificate_sha256":"..."}
```

이 레코드에는 주소·서버 PID·데이터 경로·공개 인증서 위치와 지문만 들어갑니다.
`certificate_sha256`는 **인증서 DER 바이트의 SHA-256 지문**을 소문자 16진수로
표현한 값이며 PEM 파일 자체의 해시가 아닙니다. 쿠키·CSRF·서버 capability는 출력하지
않습니다. 주소 자동 열기가 실패해도 출력 주소로 직접 접속할 수 있습니다.

## HTTPS 인증서 확인

기본 인증서와 개인 키는 데이터 폴더의 `tls/localhost-cert.pem`,
`tls/localhost-key.pem`입니다. localhost SAN이 있는 자체 서명 인증서를 생성하고
다음 실행에서 재사용합니다. OS·브라우저 신뢰 저장소는 변경하지 않습니다.
처음 접속할 때 자체 서명 인증서 경고가 나올 수 있습니다. 주소·인증서 지문을 직접
확인한 뒤 해당 로컬 서버에 대한 브라우저 선택을 진행하세요.
브라우저 전체의 인증서 검사 기능을 끄지 마세요.

macOS/Linux에서 공개 인증서의 지문을 확인하는 예:

```bash
openssl x509 -in "/absolute/path/to/modu-web-data/tls/localhost-cert.pem" -noout -fingerprint -sha256
```

OpenSSL은 대문자와 콜론으로 표시할 수 있습니다. 콜론을 제외하고 대소문자 구분 없이
준비 레코드의 지문과 비교합니다. 브라우저 인증서 상세의 SHA-256 값과도 비교하세요.
비밀번호나 개인 키 내용을 복사·공유할 필요는 없습니다.

이미 보유한 localhost SAN 인증서와 비공개 키를 지정할 수도 있습니다.

```bash
npm run web -- --cert-file "/absolute/path/localhost-cert.pem" --key-file "/absolute/path/localhost-key.pem"
```

두 파일을 함께 지정해야 합니다. 유효기간·localhost DNS SAN·키 일치를 검사합니다.
POSIX에서는 개인 키가 현재 사용자 소유이고 그룹·다른 사용자 접근 권한이 없어야
합니다. macOS에서는 확장 ACL이 있는 키도 보수적으로 거절합니다. 잘못된 기존 파일,
일부만 남은 기본 인증서 쌍, 링크 파일은 자동으로 덮어쓰거나 권한을 바꾸지 않습니다.
경로와 키/부모 폴더의 ACL을 확인한 뒤 두 파일을 명시적으로 복원·교체하세요.
Windows에서는 아직 이 개인 키 보호 검사가 구현되지 않아 실행을 중단합니다.

## 로그인, 저장, 재시작

터미널에서 설정한 로컬 관리자 계정으로 로그인합니다.

1. 처음 접속하거나 새로고침하면 **브라우저 계정 로그인** 화면이 먼저 열립니다.
   현재 HTTPS 주소를 확인하고 **공유 계정 이름**, **공유 계정 비밀번호**를 입력한 뒤
   **연결·로그인**을 누릅니다. 이 화면에서는 주소를 바꾸지 않습니다.
2. 로그인과 저장 프로젝트 확인이 끝나면 작업 화면이 열립니다.
   상단 프로젝트 이름의 **프로젝트 관리**를 엽니다.
   **새 프로젝트**에서 이름과 검사 유형을 정해 만듭니다. **최근 프로젝트** 또는
   **폴더에서 열기**로 권한이 있는 기존 작업을 열 수도 있습니다. 복원본은 같은
   프로젝트 ID를 보존하면서 별도 위치로 등록됩니다.
3. **모두 보기**로 전환하면 전체 학습 설정을 볼 수 있습니다. 데이터 준비의
   **검증된 데이터 버전**에서 ZIP을 올려 검증·채택합니다. 채택 후 **이 ZIP으로 작업 시작**을
   별도로 눌러 작업 소스로 선택하고, 라벨과 분할을 저장합니다.
4. 모델 학습에서 장치·배치·횟수·입력 크기·시간 제한을 정하고 **로컬 준비 검사** 후
   **선택 설정으로 학습 시작**을 누릅니다. 학습에는 해당 모델의 가중치가 필요합니다.
   이번 검증은 이미 있던 공식 ResNet18 캐시를 사용했으며 실행기가 내려받지 않았습니다.
5. 저장 모델을 평가하거나 다시 열 때는 **작업 센터 → 저장 작업 다시 열기**에서 완료된
   학습을 고른 뒤 **완료 후보 평가로 이동**을 누릅니다. **평가 이력 · 제품/Lot별 오류**의
   **모델별 저장 평가**에서 기존 평가를 확인합니다. 단계 이동만으로 모델이 선택됐다고
   판단하지 마세요.

학습·평가는 이 PC의 Python 엔진과 설치된 장치·모델을 사용합니다.
[브라우저 작업 흐름과 권한](extension-contracts.md#browser-studio)을 참고하세요.

새로고침·재실행·세션 만료 뒤에는 다시 로그인하고 기존 프로젝트·작업 센터를 엽니다.
남아 있는 브라우저 쿠키만으로 작업 화면을 열지 않습니다. 같은 데이터 폴더를 사용하면
계정·프로젝트·저장 작업은 유지되므로 새 프로젝트를 만들 필요가 없습니다.
기본 웹 데이터 경로는 다음과 같습니다.

| OS | 기본 데이터 폴더 | 실행기 지원 상태 |
| --- | --- | --- |
| macOS | `~/Library/Application Support/Modu Vision Web` | 기존 웹 흐름과 native 자료·라벨 교환 확인, 새 로그인·마스크·백업 복원 수락 진행 중 |
| Linux | `$XDG_DATA_HOME/modu-vision-web`, 미설정 시 `~/.local/share/modu-vision-web` | 런타임 미검증 |
| Windows | `%LOCALAPPDATA%\Modu Vision Web` | TLS 키 ACL 검사 미지원으로 실행 불가 |

Electron의 데이터나 저장소 `projects/`를 자동으로 가져오지 않습니다.
`--data-dir`은 웹 전용 새 폴더를 지정하세요. 계정 DB만 기존 데스크톱 프로젝트에
복사해 연결하지 마세요. 관리되는 artifact 바이트는 웹 데이터 폴더의 기존 기본 구조인
`projects/.artifact-objects/`에 저장합니다. 이 실행기는 상속된
`VISION_ARTIFACT_OBJECT_ROOT`, `VISION_ARTIFACT_S3_BUCKET`, `VISION_ARTIFACT_S3_ENDPOINT`를
무시하며, 기존 객체 파일을 이동하지 않습니다.

종료는 실행한 터미널에서 **Ctrl+C**를 누릅니다. 열린 HTTP 스트림은 최대 5초의 요청
정리 대기 후 닫고 기존 backend lifespan을 실행합니다. 학습 작업의 종료·분리는 기존
엔진의 detach·작업 원장·복구 정책을 따릅니다. 서버 종료가 학습 강제 종료를 뜻하지
않습니다. 재실행 시 같은 폴더를 열어 작업 상태를 확인하세요.
데이터 폴더 잠금은 서버 인스턴스의 소유를 나타내며 detached worker나 물리 GPU의
독점 사용을 보장하지 않습니다. 데스크톱과 웹은 저장 공간이 달라도 물리 GPU를
공유하므로 동시에 학습할 때 자원 사용을 확인하세요.

## 폴더 선택과 앱 기능

폴더·파일 선택이나 도우미를 처음 사용할 때 보조 프로그램이 정확한 HTTPS 주소와
로컬 계정 이름을 표시합니다. 이 컴퓨터 소유자가 허용한 뒤 해당 기능을 사용합니다.
브라우저 로그인과 컴퓨터 소유자의 네이티브 허용은 별개입니다. 선택 창 취소는
파일 변경을 일으키지 않습니다. 계정·프로젝트·라벨 세트가 바뀌면 이전 선택을 다시
사용할 수 없습니다.

이미지·라벨·마스크·모델·runtime 입력은 선택한 프로젝트 안에 읽기 전용 사본을
만든 뒤 기존 검사를 거칩니다. 원본을 옮기거나 덮어쓰지 않습니다. 가져오기에는
파일 100,000개·총 32 GiB·폴더를 포함한 항목 200,000개 한도가 있습니다. 외부 폴더를 직접 작업 소스로 연결하는
경로 입력은 프로젝트 멤버도 그 자료를 읽을 수 있음을 확인한 뒤 사용하세요.
링크가 포함된 자료는 별도의 대상 확인과 사본 만들기를 거칩니다. 이 경로는
파일 10,000개·4 GiB·링크 32개·깊이 24·메타데이터 항목 25,000개·메타데이터 8 MiB로
제한하며, 확인 전에는 파일 내용을 읽지 않습니다.
일반 공유 서버는 링크를 따라 읽지 않습니다. 네이티브 HTTP 요청은 8 MiB와 본문 수신
30초 한도를 적용합니다. 폴더 반입은 HTTP로 파일 전체를 보내는 방식이 아닙니다.

프로젝트 백업은 검증된 ZIP과 영수증을 남깁니다. 복원은 새 폴더에서 진행하며
원본과 복원본의 프로젝트·모델·라벨 세트 ID는 유지합니다. 최근 프로젝트의 위치를
확인해 원하는 사본을 선택하세요. 중단된 복원은 **프로젝트 관리**의 복구 목록에서
실제 완료 위치를 확인합니다. 공개된 결과의 등록만 마칠 수 있는 경우와 수동 확인이
필요한 경우를 구분하며, 불명확한 작업을 자동 재실행하지 않습니다.

보고서는 브라우저로 실제 HTML·JSON 바이트를 내려받습니다. 화면 미리보기는
스크립트·외부 통신을 허용하지 않는 격리 문서입니다. 프로젝트 결과 폴더와 허용된
문서는 OS에서 열 수 있지만 실행 파일·앱 번들·비밀 저장소는 열기 대상이 아닙니다.

ChatGPT 도우미의 연결·모델 선택·대화·취소·쓰기 확인은 기존 앱 서비스를 재사용합니다.
계정 정보는 로컬 계정별 OS 보호 저장소에 분리하며 브라우저에 키를 반환하지 않습니다.
실제 ChatGPT 로그인·플랜 동의·요청은 사용자가 진행해야 하며, 합성 공급자 검사가
실제 계정·요금·한도·이미지 전송 검증을 뜻하지 않습니다.

업데이트·portable 전환·OS 서비스 도구는 기존 서명·대상 OS·소유자·관리자 검사를
그대로 거칩니다. 소스 실행 보조 프로그램은 설치형 배포물이 아니므로 업데이트
대상이 없다고 표시할 수 있습니다. OS 서비스 등록에는 로컬 네이티브 허용도 필요하며,
버튼을 명시적으로 누르기 전에는 설치·배포하지 않습니다.

## 다른 공유 서버 연결

먼저 이 PC의 로컬 계정에 로그인한 뒤 **공동 작업 서버**에서 원격 HTTPS 주소를
입력합니다. 명시적으로 만든 loopback HTTP 터널도 사용할 수 있습니다. 원격 서버의
계정·프로젝트 권한은 그 서버가 판단합니다. 원격 세션 토큰은 localhost 서버 메모리에
두며 브라우저에 보관하지 않습니다. 로컬 쿠키와 CSRF를 원격 서버로 전달하지 않습니다.

로컬 프로젝트 문맥과 원격 프로젝트 문맥은 분리합니다. 서버·계정·프로젝트를 바꾸면
이전 요청·WSS를 폐기하며, 연결 종료 후에는 로컬 계정으로 돌아옵니다. 다른 탭의
정상 작업을 함께 취소하지 않습니다. 서버 주소를 바꾼 뒤에는 새 프로젝트가 실제로
선택됐는지 확인하세요.

## 서버와 보조 프로그램 상태

기술 상세에는 인증된 localhost 서버 PID와 보조 프로그램의 실제 PID를 따로 표시합니다.
서버가 응답해도 보조 프로그램 연결은 끊길 수 있습니다. 이 경우 저장된 작업 상태와
실행 터미널의 `native-host/helper.log`를 확인하고 같은 데이터 폴더로 다시 실행하세요.
자동으로 다른 프로세스를 종료하거나 실행 중인 학습을 다시 시작하지 않습니다.

## 실행 오류

- **포트 사용 중:** 해당 소유 프로세스를 확인하거나 `--port 8444`처럼 포트를 바꿉니다.
  실행기는 다른 프로세스를 종료하지 않습니다.
- **같은 데이터 폴더 실행 중:** 먼저 실행한 서버 터미널을 확인합니다. 잠금 파일을
  지우거나 PID만 보고 프로세스를 종료하지 마세요. 정상 종료·프로세스 종료 뒤에는
  OS 잠금이 해제되므로 같은 폴더로 다시 실행할 수 있습니다.
- **첫 계정 입력 불가:** 일반 터미널에서 같은 `--data-dir`로 실행해 계정을 설정합니다.
- **renderer 빌드 실패:** 기존 `npm ci` 설치와 오류 출력을 확인합니다. 실행 중 자동
  설치는 하지 않습니다. 링크가 있는 출력 폴더는 빌드 전에 거절합니다.
- **Python 실행 불가:** 기존 의존성이 설치된 Python의 전체 경로를 `VISION_AI_PYTHON`에
  지정합니다. 이 실행기는 의존성을 추가하지 않습니다.
- **인증서 오류:** 오류의 경로·유효기간·SAN·키·권한/ACL을 확인합니다. 기존 파일을
  보존한 상태에서 사용자가 명시적으로 쌍을 복원·교체해야 합니다.
- **준비 확인 실패:** 브라우저를 열지 않고 자신이 시작한 서버만 정리합니다. 출력된
  원인을 확인한 뒤 같은 명령을 다시 실행하세요.
