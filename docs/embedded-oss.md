# 모두비전 안에서 사용하는 오픈소스

별도 라벨링 사이트나 실험 관리 서버에 접속하는 대신, 필요한 알고리즘과 라이브러리를 기존 모두비전 화면·저장 이력·CLI·도우미 실행기에 연결합니다. 새 알고리즘은 이 PC에서 실행하며 외부 수집 서버를 요구하지 않습니다. ChatGPT 계정 연결 자체를 로컬 모델로 바꾸는 기능은 아닙니다.

## 단계별 적용

| 구간 | 내재화한 부분 | 사용 방법과 범위 |
| --- | --- | --- |
| 1 데이터 준비 | 기존 Pillow·OpenCV 입력 처리와 원본·분할 기록 유지 | 새 검토 순위도 저장된 자료·분할·정답의 식별자를 확인합니다. 원본을 자동 수정하지 않습니다. |
| 2 라벨 달기 | cleanlab 2.9의 normalized-margin 계산 일부를 NumPy 코드로 내장 | 저장된 공통 시험 묶음의 **분류 평가**를 선택하고 라벨 재확인 순위를 만듭니다. 기존 검토 큐에서 낮은 점수부터 확인합니다. |
| 3 모델 학습 | Optuna 5 TPE 후보 제안 | 자동 탐색에서 후보 예산이 8개 이상이면 기본 `auto`가 적응형 탐색을 선택합니다. 작은 탐색·빠른 학습은 기존 결정형 탐색을 유지합니다. |
| 4 결과 평가 | COCO 구현과 대조한 검출 AP v2 | 새 객체 검출 평가에 적용합니다. 계산 정의를 저장하고 과거 점수를 소급 변경하지 않습니다. |
| 5 검사 흐름 | 기존 편집기에 키보드 이동·초점·실행 취소 보완 | 노드에 초점을 둔 뒤 방향키 10px, Shift+방향키 50px 이동. 연속 이동은 한 번의 실행 취소로 되돌립니다. 검색 결과로 이동하면 실제 노드에 초점이 갑니다. Escape로 연결 중인 선·선택을 해제합니다. |
| 6 검사·전 구간 진단 | 기존 ONNX Runtime/OpenVINO 경로 유지, OpenTelemetry SDK 로컬 기록 | 지원되는 HTTP 읽기와 도우미의 실제 호출 시간을 기존 진단 도구에서 확인합니다. 별도 대시보드·수집기는 설치하지 않습니다. |

Label Studio 전체 제품을 이식한 것은 아닙니다. 라벨링 정밀 편집과 이 내재화 기능은 현재 소스에 통합되어 있으며, 원래의 독립 검토·검증 기록은 보존합니다. 기존 PyTorch·이미지 처리·추론 엔진을 다른 플랫폼으로 중복 교체하지 않습니다.

## 라벨 재확인 순위

저장된 분류 평가의 전체 클래스 확률, 클래스 순서, 현재 자료·정답·체크포인트·시험 묶음의 일치를 검증합니다. 누락된 확률이나 과거 형식은 추측해서 채우지 않습니다. 예측이 맞은 이미지도 다른 클래스와 점수 차이가 작으면 순위에 남습니다.

점수는 **재확인할 순서**이며 오라벨 확정이나 품질 합격 표시가 아닙니다. 데이터 독립성도 이 계산만으로 입증하지 않습니다. 라벨을 고친 뒤 기존 큐를 이어갈 수 있지만 당시 분석 기준이 바뀌었다고 표시합니다. 같은 오래된 분석으로 새 큐는 만들 수 없으며, 원본 이미지나 고정한 버전 백업이 손상되면 진행을 거절합니다. 도우미에는 “저장된 분류 평가로 라벨 재확인 순위를 만들어줘”라고 요청할 수 있습니다. 실제 평가 ID가 필요합니다.

## 적응형 탐색과 재현

Optuna는 기존 학습 조정기 안에서 다음 후보를 제안합니다. 학습 실행·자원 임대·취소·원격 작업 소유권·시간 및 epoch 예산은 기존 엔진이 관리합니다. 중복 제안은 실행 예산을 소비하지 않으며, 검증된 완료 영수증과 체크포인트가 저장된 뒤에만 결과를 sampler에 전달합니다.

REST의 `search_strategy` 또는 학습 CLI의 `--search-strategy`는 `auto`, `deterministic`, `adaptive`입니다. `seed`도 기록합니다. sampler 버전·도메인 해시·제안 순서와 선택된 설정이 저장됩니다. 설정 재실행은 새 study이며 optimizer 상태를 정확히 이어받는다고 주장하지 않습니다. 모든 모델군에 공통 검증된 중간 점수 계약이 없어 pruning은 사용하지 않습니다. SSH 후보 실행도 sampler는 로컬 조정기에서 돌며 원격 worker에 Optuna를 설치할 필요는 없습니다.

## 검출 점수의 계산 기준

`detection-ap-v2`는 일반 bbox, 전체 면적, crowd/ignore가 없는 입력, 이미지·클래스당 상위 100개 예측을 대상으로 합니다. 정답이 없는 클래스는 AP 평균에서 제외하고, 이미 매칭된 정답 대신 다음 사용 가능한 정답을 찾습니다. 전체에 객체 정답이 없으면 AP는 0점이나 100점 대신 **계산 불가**입니다. crowd/ignore 입력은 이 범위 밖입니다.

과거 계산 기준은 `detection-ap-legacy-v1`로 남으며 버전 표시가 없는 옛 기록도 같은 기준으로 읽습니다. 다른 기준의 점수를 직접 전후 성능 향상으로 비교하지 마세요. 계산 정확성은 합성 bbox와 실제 pycocotools 2.0.11 결과로 대조했고, 현장 모델 정확도가 개선됐다는 뜻은 아닙니다.

## 로컬 진단과 CLI

도우미의 기존 `read_app_diagnostics`에서 `traces`를 선택합니다. 확인된 직접 로컬 HTTP 경로에서는 도우미 호출 → API → 백엔드의 시간·성공·상태를 연결합니다. 원격·네이티브 어댑터와 비동기 작업은 연결을 입증하지 않은 별도 관측으로 표시합니다. 실패 이력은 기존 진단 목록에도 계속 남습니다.

세션 범위당 최근 256개, 최대 8개 범위만 메모리에 보관하며 누락 개수를 표시합니다. 내보낸 JSON은 1MiB 상한입니다. 이미지·질문·응답 본문·토큰·폴더 경로는 span에 넣지 않고, 계정·프로젝트와 로컬 범위가 바뀌면 이전 결과를 채택하지 않습니다. 외부 exporter나 collector는 없습니다.

공통 CLI도 실제 서버의 schema로 새 엔드포인트와 필드를 찾습니다. 접속·인증 방법은 [CLI 안내](studio-cli.md)를 따르세요.

```sh
python -m backend.studio_cli describe "POST /api/data-workbench/label-quality-analyses"
python -m backend.studio_cli describe "POST /api/training/start"
```

## 소스·배포 범위

| 구현에서 선택한 것 | 얻는 것과 남는 비용 |
| --- | --- |
| cleanlab 계산만 선별 이식 | 작은 로컬 의존성. 전체 오류 탐지 제품의 기능·독립성 보장을 제공하지 않음 |
| 기존 검토 큐에 참고 순위 연결 | 검토 위치·라벨 편집 이력 유지. 낮은 점수를 자동 정답 수정이나 품질 승인으로 쓰지 않음 |
| Optuna를 기존 조정기에 부착 | 실행 예산·취소·원격 소유권 유지. 작은 기본 탐색은 결정형이며 pruning/정확 optimizer 재개 없음 |
| 새 AP 계약과 과거 계약 분리 | 저장된 근거 보존. 이전/새 점수의 직접 비교 제한, 원본 좌표 정답을 위한 추가 CPU decode 비용 |
| 로컬 SDK와 명시적 부모 연결 | 외부 수집 서버 없이 호출 진단. 변환하지 않은 remote/native/비동기 worker는 연결 미확인 |
| 기존 흐름 캔버스 개선 | 저장 graph/실행 의미 보존. 다른 그래프 제품 전체의 기능을 가져온 것은 아님 |

cleanlab은 선택한 계산만 이식했으며 전체 패키지는 의존성에 추가하지 않았습니다. [원본 라이선스·수정 고지·해시](../third_party/cleanlab/provenance.json)를 보존하고 웹 정적 자료와 frozen backend 리소스에도 포함합니다. Optuna·OpenTelemetry는 버전을 고정하고 플랫폼별 CPU lock·빌드 목록·[외부 구성 요소 고지](../THIRD_PARTY_NOTICES.md)에 반영합니다.

이 문서는 현재 소스에 구현된 기능과 그 지원 범위를 설명합니다. 사용 중인 설치 앱·웹의 실제 버전, 모든 OS의 설치 수락과 현장 품질은 별도로 확인합니다. [이번 검증 범위와 남은 조건](verification/2026-11-14-embedded-oss.md)을 확인하세요.
