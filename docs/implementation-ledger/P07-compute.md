# P07 — compute allocation and remote family jobs

Date: 2026-09-30. Scope: F083–F089. Baseline: `a4d3610`. This ledger distinguishes implemented paths, CPU functional results and unperformed GPU/field acceptance.

## Implemented paths

- Cross-process SQLite reservations include host, observed device UUID/parent UUID, memory budget, task, project/account ownership and a renewable owner lease. Independent GPUs and separate MIG children are disjoint. A physical GPU blocks its children. Unobserved MIG selectors remain conservative. Probe-observed identical UUIDs also bind two SSH aliases to one capacity. Ambiguous/disconnected remote jobs retain their claims until reconciled; foreign owners cannot release or heartbeat them.
- Explicit GPU sharing requires one observed device, a positive per-job memory budget and total claims within observed capacity. Workers apply the reserved fraction to the actual CUDA allocator before constructing models. The existing exclusive behavior remains the default. Inventory changes cannot raise an active claim's capacity.
- SSH profiles support `memory_budget_mb`, `allow_sharing` and `distributed_processes`. Actual `nvidia-smi` inventory and optional NVML enumerate physical/MIG identities and memory. Unsupported MIG dependencies/hardware report their prerequisite. Profiles/SSH configuration are administrator-only on shared servers; targets expose safe names/allocation settings and reservations are project-scoped.
- Training worker dispatch uses the real measured core and specialist engines for Classification, Patch, Detection, Segmentation, Anomaly, Rotation, OCR, OBB, Enhancement and DefectGAN. Owned prepared data and canonical original-source snapshots are separately hash-bound. Context-local source aliases verify the portable copy while retaining original manifest bytes and canonical provenance.
- Native specialist model IDs remain 32-hex IDs. Remote worker/coordinator IDs are `job_<same-id>`, with both identities validated and persisted. Patch retains the core `models/job_*` path. Received checkpoints are verified before deterministic dataset-path relocation, and original received hashes are recorded separately from final local hashes. Native model discovery, inference and warm-start reopen the downloaded result.
- Worker inference executes actual engines for every training family, including review-only GAN generation. Core and specialist inference, full-flow execution, evaluation/export/benchmark operations share the reservation owner/uncertain-state rules. A completed job's source image can be checked through the compute UI and a hash-verified PNG result returned.
- Label workers use actual SAM2/DINOv3/Grounding provider prerequisites, produce pending candidates and transfer a job/snapshot/hash-bound result. Import verifies original images, overlays, label set/version and provider baseline, then creates existing pending suggestions and a completed review batch. Only explicit existing review adoption writes project-owned overlays after backup; source images/LabelMe files remain unchanged.
- One model can run on multiple actual torch distributed rank processes. Classification/Patch/Segmentation support CUDA/NCCL and CPU/gloo; unsupported adapters/devices fail explicitly. Train samplers partition input, validation covers the complete holdout on every rank, epoch sampler seeds advance, loss is reduced with weights, and cancellation synchronizes at matching collective boundaries. Only primary rank publishes unwrapped checkpoints/progress. The launcher owns and terminates its entire process group.
- Native compute controls provide server allocation, queue/status/cancel/reconnect, specialist prepared input, label result import and selected-image server inference. Account/server/project changes reset cached profiles, drafts, reservations/jobs and ignore delayed responses from an old transport.

## API contracts

- `GET /api/compute/{capabilities,targets,inputs?task=...,reservations}`; administrator `GET /devices` and profile CRUD/probe/selection.
- `POST /api/compute/jobs`: `{task, operation:'train'|'label', dataset_path:<registered canonical source>, family_dataset_path?:<owned preparation>, compute_profile_id, preset?, device?, config_overrides?, labeling?, dataset_version_id?}`. Returns 202 `{job_id,model_id,task,operation,status,phase,compute_profile_id,current_epoch,total_epochs,current_step,total_steps,metrics,best_metric,error,submitted_at}`.
- `GET /jobs`, `GET /jobs/{id}`, `POST /jobs/{id}/{cancel,reconnect}`, `GET /jobs/{id}/results`. Completed result readback rechecks persisted artifact byte count and SHA.
- `POST /jobs/{id}/label-proposals` → `{batch_id,proposals:[existing foundation suggestion records]}`. Import is idempotent; no automatic adoption/quality approval.
- `POST /jobs/{id}/predict`: `{image_path:<registered project image>,threshold?}` → actual task output, `model_id`, `compute_profile_id`, `predictions`, `overlay_base64`, `latency_ms` and optional confidence. Uses the frozen training server and its owned inference reservation. GAN output is `synthetic_unreviewed`, with no automatic approval.
