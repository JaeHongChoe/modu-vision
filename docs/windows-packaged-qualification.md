# Hosted Windows unsigned packaged CPU qualification

The manual `Windows unsigned packaged CPU qualification` workflow builds on Windows Server2025 x64 with the existing locked CPU environment and five pinned build-only compiler packages. It builds unsigned NSIS and portable artifacts, then launches the actual `win-unpacked` executable with isolated owned Korean/space userData. It never runs the installer or registers services.

The packaged renderer sends the production classification CPU preflight request. Pass requires real frozen backend and internal CPU child executable identities/hashes, four train/evaluate/infer/export stages, an actual OK/NG inspected-image export, observed checkpoint/known-image hashes, and identical persisted stage evidence after app restart. Source fallback, incomplete CPU results, changed evidence, wrong executable or missing subprocess identity fail. The observer reads only owned descendants and allowlisted temporary preflight artifact hashes; it does not export command lines, environment, headers or private userData. The temporary production preflight normally removes its run artifacts; receipt hashes are observations made while those files exist, not retained checkpoint delivery.

Private temporary-state cleanup is part of qualification: final receipts are written after its result, and a locked cleanup failure persists failed status with a typed code, never a passing receipt. The always-run inventory cannot promote that failed app proof.

Failure receipts, sanitized harness errors, screenshots, frozen/build diagnostics and artifact hashes are retained seven days. A successful job is evidence for its exact hosted Server build and unsigned executable, not Windows11 clean-machine non-admin installation, signed release, VC redistributable installation, update/rollback, uninstall, field devices or model quality. Python/Node remain installed on the build runner. The harness validates actual frozen execution rather than pretending this runner is a clean target.

The release hooks remain unchanged. PyInstaller supports Python3.13 by metadata; actual freezing of the scientific stack and native acceptance must pass in this job. Builder helper downloads are build tooling recorded by cache-file hashes; the workflow does not claim bit-for-bit reproducibility. No secrets, GPU connection, administrator/system installation or GitHub release publishing is configured.
