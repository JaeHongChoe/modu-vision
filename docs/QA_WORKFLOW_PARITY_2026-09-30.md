# Workflow 기능 벤치마킹 구현 QA · 2026-09-30

## 판정 범위

격리된 데스크톱 개발 앱에서 고객 제공 검사 이미지 88장(주석 있음 80장, 없음 8장)을 사용했다. 학습·검증·시험 분할은 56/16/8이다. 정상(OK) 표본이 대표성 있게 포함되지 않아 이 결과는 기능 검증이며, 과검률·모델 품질·양산 승인 근거가 아니다. 고객 원본, 주석, 프로젝트 경로, 이미지 파일명, 체크포인트 ID와 상세 검사 결과는 Git에 넣지 않았다.

## 실제 데이터로 확인한 기능

| 단계 | 확인한 동작 | 범위 |
| --- | --- | --- |
| 1 데이터 | 프로젝트를 다시 열어 88/80/8장과 56/16/8 분할을 재확인했다. 데이터 버전은 171개 이미지·라벨 파일을 검사해 변경 0건이었다. 라벨 유무 필터는 원본 80장/8장을 각각 반환했고, 프로젝트 주석을 비우거나 추가하는 회귀 시험에서도 상태가 갱신됐다. | 라벨이 바뀌면 과거 분할에 남은 무효 이미지가 갤러리 학습 탭에서 제외된다. |
| 2 라벨링 | 완료 모델로 라벨 없는 실제 이미지 8장에 검토용 후보를 일괄 생성했다. 첫 실행은 8/8 완료·실패 0·후보 0건이었다. 최신 앱 재실행은 8/8 완료·실패 0이며 한 이미지에 polygon 후보 6개가 생성됐다. 해당 이미지의 검토 버튼을 눌러 원본 위의 후보와 선택 항목을 확인했다. 앞선 실행에서 입력 이미지 8장의 SHA-256 전후 동일성을 확인했다. 별도 완료 모델은 실제 결함 이미지에서 후보 1개를 선택 채택·버전 백업·원본 불변으로 검증했다. | 후보 생성과 채택은 별도 단계다. 최신 6개 후보는 채택하지 않았다. 후보 개수는 임계값과 모델 결과에 따라 달라지며 라벨 품질을 입증하지 않는다. |
| 4 평가 | 네이티브 앱에서 완료 세그멘테이션 모델 두 개를 같은 고해상도 시험 이미지에 적용했다. 기준 NG→후보 OK의 원판정 불일치 1건이 저장된 비교 카드에 표시되고 재열기에서도 같았다. | 양쪽 클래스가 없는 데이터라 과검·미검률이나 후보 우수성을 판정하지 않았다. CPU 한 장 처리에 약 4분이 걸려 UI에 소요 안내를 넣었다. |
| 5 플로우차트 | 검출→ROI 분할의 저장 버전 둘을 전환하고 동일 이미지에서 임계값에 따라 ROI 0개/REVIEW와 ROI 4개/NG를 확인했다. 고정 ROI 노드는 원본 픽셀 좌표를 유지하며, 실제 이미지와 체크포인트로 엔진/독립 패키지 결과 일치를 확인했다. | 5개 서로 다른 체크포인트를 연결한 현장 검사는 아직 검증하지 않았다. 회전 ROI·마우스 드래그 편집은 지원하지 않는다. |
| 6 검사·내보내기 | 최신 서버 판정 경로에서 활성 저장 버전으로 시험 이미지 8장을 다시 검사해 NG 6, REVIEW 2, 실패 0을 얻었다. 검사 당시 플로우 버전·그래프 해시·두 체크포인트 해시가 이력에 남았다. 작업자 REVIEW 사유를 원판정과 별도로 저장했고, 앱 재시작 후 완료 이력과 사유를 재확인했다. 검사 중 5단계로 이동한 별도 실행은 2장 처리 후 중단되고 6장이 미실행으로 남았으며, 재시작 후에도 유지됐다. 기존 CSV·JSON 재열기와 전체 플로우 패키지 SHA-256 manifest 및 실제 이미지 앱/독립 실행기 판정·ROI 일치도 확인했다. | 서버 판정 경로에서 발견한 저장 그래프의 `50.0`/`50` 왕복 차이는 수정하고 회귀 테스트를 추가했다. 패키지 실행은 현장 장비·PLC·택트시간 승인과 다르다. |
| 원격 자원 | 외부 GPU 프로필에서 검출→분할→분할을 실제 이미지에 실행했고 ROI 4개, NG, 노드별 trace 및 자원 반환을 확인했다. | 한 환경에서 검증한 결과다. 모든 서버·GPU 조합을 입증하지 않는다. |

## 검증 결과와 남은 범위

- 백엔드 전체 회귀 `python -m pytest backend/tests -q --disable-warnings`: **690 통과, 11 건너뜀**. 서버 판정 그래프 숫자 왕복 수정 후 검사 이력 집중 테스트 **12 통과**.
- TypeScript 타입 검사와 제품 빌드가 통과했다. 검사·플로우·버전 인계 Node 집중 테스트 **70 통과**와 프로젝트 전환 회귀 스크립트가 통과했다. 빌드에는 기존 동적 import와 큰 JS 청크 경고가 남아 있다.
- 5단계 저장·활성 버전, 6단계 다음 검사 대상, 검사 당시 버전은 앱에서 구분되어 보였다. 화면 이탈 중단과 재시작 후 완료 행·작업자 이력 복구를 확인했다.
- 동일 원본 폴더를 쓰는 프로젝트 간 라벨·분할·모델 후보·검사 이력 분리는 백엔드 통합 테스트로 확인했다. 실제 앱의 프로젝트 A→B 전환 중 검사도 별도 네이티브 QA가 필요하다.
- 고해상도 모델 비교는 진행·취소·원격 계산을 추가하기 전까지 오래 걸리는 동기 작업이다.
