Status: source contract review and one isolated synthetic source-CLI rotation run, 2026-11-14. All ten catalog families remain in scope. **Current candidate packaged execution, physical target qualification, human usability and customer quality are pending for every family.** The catalog sets `quality_approved=False` throughout.

## Shared execution boundaries

The [catalog](../backend/engine/model_catalog.py) is authoritative for prerequisites, detected devices, missing dependencies and stages. Selection does not execute work. CPU/MPS/CUDA availability depends on the actual runtime. Missing dependencies or compatible weights block execution; capability presence is not readiness. DINOv3/YOLO defaults require genuine compatible weights; offline checkpoints require their hashes, with no silent random-weight substitution.

The [folder/JSON CLI and authenticated REST](training-engine-cli-rest.md) expose preparation, training, durable status, evaluation and output artifacts. The [recipe matrix](../backend/engine/execution_recipe.py) declares training/evaluation for all ten families, prediction/flow for all except GAN, and generation only for GAN. Capture live capabilities for the exact route: catalog architectures and automatic runner search options differ. `remote_training` derives from the loaded runner registry, not the historical definition tuple's boolean; it does not qualify a remote connection/device.

External-label preparation requires explicit nonempty train/val/test partitions; identical bytes cannot cross partitions. Photos alone do not supply truth. The [fixed input-rule editor](training-input-preparation.md) currently supports classification/segmentation; other families retain native preparation paths.

## Evidence required to update a cell

Retain commit/artifact hash, live capability response, environment/dependencies/device, immutable data/label/split identities, architecture/method and exact route/parameters, job ID and terminal result, model/evaluation hashes, errors and saved-flow or GAN review/adoption records. Record each skipped stage and reason. Source tests, synthetic execution, package smoke, human study and customer evaluation need distinct scope/outcome records.

Historical [lifecycle integrity notes](verification/model-lifecycle-evidence.md) describe partial family records and separate synthetic native executions. Integrity checking does not load or execute models; those records do not qualify the current candidate. Never fabricate missing receipts.
