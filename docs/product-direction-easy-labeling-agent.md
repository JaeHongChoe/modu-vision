## 2. 원칙

1. **업무 용어.** 화면 문구는 "이미지 준비 → 라벨 달기 → 학습 → 평가 → 검사 흐름 → 검사"의 말로 씁니다. 코드·영어 상태는 기술 상세에만 둡니다(이번 PR의 F-15 방향).
2. **단계마다 주된 행동 하나.** 화면에서 가장 큰 버튼은 그 단계에서 지금 해야 할 일 하나입니다.
3. **한곳의 상태 카드.** 상태, 막힌 이유, 해결 방법, 다음 행동은 하단 안내 한곳에서 봅니다. 패널 오류도 같은 곳에 요약하고, 패널에는 자세한 내용만 둡니다.
4. **상세는 접힘.** 전문가 기능은 지우지 않고 접힘 영역과 기술 상세로 옮깁니다(키보드·화면 읽기 프로그램으로 열 수 있게).
5. **초안과 정답의 구분.** 모델·도우미가 만든 것은 "초안"이고, 사람이 미리보기에서 확인해야 라벨이 됩니다. 채택 기록(누가, 언제, 어떤 모델·제안에서)을 남기고, 채택 단위로 되돌릴 수 있어야 합니다.
6. **쉬움은 재서 확인한다.** 목표 사용자는 "현장에서 처음 검사 프로그램을 쓰는 비개발자"입니다. 통과 기준: 이미지 폴더 하나로 시작해 첫 검사 흐름 저장까지 **30분 이내**, 그 경로의 필수 클릭 **40회 이내**(첫 실측 뒤 조정), 모든 막힘에 한국어 이유와 해결 행동이 하나씩 붙음. 이 수치는 실제 앱 QA에서 시간과 클릭 수를 세어 확인하고, 기준을 못 넘기면 그 화면이 다음 작업입니다.
7. **인터넷 없이도 그대로.** 도우미·외부 모델이 없거나 꺼져 있어도 1~6단계는 지금처럼 다 됩니다.

### 3.2 첫 구현 범위: "초안 검토" 화면

- 2단계 간단히 보기의 주 행동을 "초안 검토"로 둡니다(학습 모델이 없으면 "직접 라벨 달기", 모델이 있으면 "초안 만들기 → 검토").
- 초안 원천은 기존 label-suggestions(학습 모델)와 label-candidates입니다. 새 모델 실행 경로를 만들지 않습니다.
- 목록 순서: 기본은 "모델이 헷갈리는 것부터"(후보 최고 신뢰도가 기준값 근처이거나 낮은 것), 선택으로 "확실한 것부터"(일괄 채택용). 화면에 순서 기준을 씁니다.
- 일괄 채택·거절: 여러 장을 고른 뒤 미리보기(겹쳐 보기)에서 확인하고 채택합니다. 이미 사람이 그린 라벨이 있는 이미지는 기본으로 "덧붙이기"이며, 바꾸기는 그 이미지에서 따로 확인합니다.
- 출처 기록: 채택한 도형에 `origin`(종류 `model_draft`, 제안 ID, 모델 해시, 채택한 사람, 시각)을 저장합니다. `AnnotationItem`에 선택 필드로 더해 기존 파일과 호환을 유지합니다.
- 되돌리기: 채택마다 "이 채택 되돌리기"를 둡니다. 채택 뒤 그 도형이 바뀌지 않았으면 그 도형만 빼고, 바뀌었으면 이유를 보여 주고 데이터 버전 복원(채택 전 자동 백업)으로 안내합니다.
- 운영 주기의 `_auto_label`은 바로 쓰지 않고 같은 초안 저장소에 넣도록 바꿉니다(기본 꺼짐은 유지).
- 하단 안내가 2단계에서 "초안 N장 검토 대기 · 확정 M장"을 알게 합니다.
- **(2026-10-22 결정) 초안 만들기에 쓰는 모델의 범위.** 채택할 때마다 데이터 지문이 바뀌어 재학습 전에는 새 초안을 못 만드는 한 바퀴(라벨 → 초안 → 채택 → 재학습)가 처리량을 묶습니다. 지문 검사는 평가·승인의 무결성용이므로, **초안 만들기만은 같은 원본으로 학습한 완료 모델이면 데이터가 바뀐 뒤 학습한 모델도 허용**하고 목록과 초안에 "데이터가 바뀐 뒤 학습한 모델 · 평가 근거 아님"을 표시합니다. 채택 시 검사(이미지·라벨·체크포인트 해시, 묶음의 검토 지문, 학습 중 거절, 편집 잠금)와 평가·승인·흐름의 지문 검사는 그대로입니다.
- **첫 라벨까지의 길(빈 프로젝트).** 모델이 없을 때의 경로를 화면에 못 박습니다: 직접 20장(또는 SAM2 클릭 보조, 2단계 뒤) → 학습 → 남은 이미지 초안 → 검토. 하단 안내의 '직접 라벨 달기'가 이 첫 구간을 맡습니다.
- **채택률 표시.** 모델(초안 묶음)마다 채택·거절·채택 뒤 수정 수를 한 줄로 보여 줍니다. 사용자가 "이 모델을 믿어도 되는지, 기준 신뢰도를 올릴지"를 숫자로 판단하게 하고, 도우미도 같은 숫자를 읽습니다.

검증 기준: 초안은 채택 전 라벨 파일·학습 데이터·데이터 지문을 바꾸지 않음(백엔드 테스트), 채택은 백업 ID와 `origin`을 남김, 되돌리기는 그 도형만 정확히 빼고 다른 사람 편집은 보존, 기존 라벨이 있는 이미지에 덧붙이기 기본, 화면 단위 테스트와 브라우저 스펙(합성 데이터), 실사용 경로(라벨 20장 → 학습 → 초안 50장 → 일괄 검토 → 재학습).

## 4. 내장 도우미(에이전트)

### 4.1 목표와 한계

도우미는 지금 열린 프로젝트·단계·오류를 이해해 "왜 막혔고 무엇을 하면 되는지"를 설명하고, 사용자가 허락한 앱 도구만 실행합니다. 학습·추론·자동 라벨 같은 계산은 지금처럼 이 컴퓨터(또는 사용자가 고른 계산 서버)에서 하고, 도우미는 계획·설명·도구 호출만 맡습니다. 판정·승인·배포는 도우미가 대신하지 않습니다.

"왜 막혔나"는 상태 카드가 이미 답하므로, 도우미의 가치는 **확인을 받으며 여러 단계를 대신 진행해 주는 것**입니다. 첫 버전이 다루는 의도 다섯 가지: ① 지금 단계에서 막힌 이유 설명과 해결 행동 열기, ② 남은 이미지의 초안 만들기(모델·기준 신뢰도 제안 → 확인 → 실행), ③ 초안 검토 안내(헷갈리는 것부터 열어 주기, 채택률 설명), ④ 학습 시작 준비(분할·가중치·장치 점검 → 확인 → 시작), ⑤ 평가 결과 풀이(놓친 불량·잘못 잡은 정상의 뜻과 기준 점수 제안). 이 밖의 요청은 "직접 하세요"와 위치 안내로 답합니다. 도우미가 꺼져 있거나 인터넷이 없으면 같은 다섯 가지를 상태 카드와 하단 안내가 그대로 맡습니다.

### 4.2 연결 방식 (2026-10-22 결정): 1차는 사용자 API 키, 2차는 Sign in with ChatGPT

**1차(먼저 구현): 사용자 API 키.** 사용자가 자기 키를 넣습니다. 공급자는 OpenAI 호환(Responses 또는 Chat Completions 형식의 주소+키, 지금 라벨 후보의 VLM 공급자와 같은 틀)과 Anthropic Messages API 두 가지를 지원합니다. 키는 Electron 주 프로세스가 OS 보호 저장소(`safeStorage`, 소유자 전용 권한)로만 보관하고 렌더러·백엔드·로그·프로젝트 파일에는 두지 않습니다(4.4와 같음). 비용은 키 소유자에게 청구되므로 요금·동의는 사용자가 결정합니다. 도구·실행 기록·확인 규칙(4.5·4.6)은 공급자와 무관하게 같습니다.

**1차 구현 (2026-10-23).** 주 프로세스 `src/main/assistant/`(키 보관 `keyStore.ts`, 공급자 `providers.ts`, 전송 경계 `service.ts`, 마지막 가림 `redact.ts`, 실행 ID 헤더 `runHeader.ts`, IPC `ipc.ts`), 화면 `src/renderer/components/assistant/AssistantPanel.tsx`와 `services/assistant*.ts`·`stores/useAssistantStore.ts`, 백엔드 실행 기록 `backend/api/routes_assistant.py`. OpenAI 호환은 Chat Completions와 Responses 둘 다, Anthropic은 Messages API이며 각 공급자의 함수/도구 형식을 그대로 씁니다(스트림 없는 한 번 호출, 화면은 "보내는 중"과 멈추기를 보여 줌). 요청 형식은 2026-10-23 공식 문서로 확인했습니다: Anthropic `POST /v1/messages`, `x-api-key`, `anthropic-version: 2023-06-01`, 도구 `input_schema`, `tool_use`/`tool_result`, 도구를 쓴 차례의 thinking 블록은 받은 그대로 돌려보냄; OpenAI Responses 함수 도구 `{type:"function", name, parameters}`와 `function_call`/`function_call_output`(`call_id`), 일부 최신 모델은 도구 호출에 Responses만 받음; Chat Completions는 호환 서버들이 구현한 `tools[].function`·`tool_calls`·`role:"tool"` 형식(공식 참조 페이지는 이 날 403/404로 열리지 않아 기존 계약으로 구현). 키가 없거나 인터넷이 없거나 도우미를 열지 않으면 아무것도 밖으로 나가지 않습니다.

**2차(약관·실제 동작 확인 뒤 선택지로): Sign in with ChatGPT.** 공식 오픈소스 로컬 앱 연결 경로를 확인했습니다. 라이브 통합·클라이언트 등록·약관 수락·실계정 호출은 아직 하지 않았으며, 사용자/조직 권한자의 약관 확인과 사용자의 직접 로그인·플랜 동의를 남깁니다. API 키 방식의 개발·검증은 독립적으로 계속합니다.

**2026-10-24 공식 근거 갱신.** [등록·로그인](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [추론](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [실제 SIWC 약관](https://openai.com/policies/sign-in-with-chatgpt-terms/)(2026-09-29판)을 읽었습니다. 과거의 약관 403은 조회 실패였으며 지원 불가의 근거가 아닙니다. 동적 등록과 시스템 브라우저 PKCE를 사용하고, 로컬 사용자 통제 토큰 보관·해당 사용자 활동/명시 동의 자동화·무료 SIWC 기능·개인정보 안내가 필요합니다. 약관은 통합/사용 자체를 동의로 규정하므로 권한자의 결정 없이 활성화하지 않습니다. 현재 API 키 공급자는 비스트림 JSON 응답을 쓰므로 토큰만 끼워 넣을 수 없습니다. 별도 SSE 어댑터(`store:false`, `stream:true`, `response.completed` 확인), 계정별 토큰 갱신·폐기와 도구 namespace 구현이 남습니다. 공식 가능성과 특정 계정의 실제 성공은 구분합니다.

2026-10-21에 공식 문서(quickstart, open-source sign-in, Codex app-server, models and inference, accounts and sessions, errors and recovery, token reference, preview limitations, UI/UX guidelines)를 직접 확인했습니다. 이 저장소는 MIT 라이선스(`LICENSE`)이고 사용자는 오픈소스로 배포한다고 확인했습니다. 문서는 오픈소스·로컬 실행 앱에 ChatGPT 플랜 사용을 열어 두고 있으며("ChatGPT plan usage is available to all open-source partners and selected private clients"), 비공개 앱의 제공 대상 제한은 이 프로젝트의 선행 장벽으로 두지 않습니다. 유료 또는 원격 호스팅 형태로 제공하려면 별도 신청(interest form)이 필요하다고 되어 있으므로, 공유 서버가 사용자 대신 토큰을 들고 호출하는 형태는 이번 범위에서 뺍니다.

- **별도 API 키 없음.** 사용자는 브라우저에서 ChatGPT 계정으로 로그인하고 "이 앱이 내 ChatGPT 플랜을 쓰는 것"에 동의합니다. 앱은 OAuth 토큰으로 Responses API를 호출합니다. 클라이언트 비밀값이나 개발자 API 키를 앱에 넣지 않습니다.
- **처음 등록.** 처음에는 `client_id=dynamic_agent_client`로 인가를 시작하고 `ext_agent_host_id`(이 컴퓨터의 불투명 식별자: `urn:uuid:`+UUIDv4, JWK 지문 URI 또는 `did:key` 형식만; 이메일·사용자 ID가 아닌 값)와 `agent_name_hint`(앱 이름, 처음 등록에서만)를 보냅니다. 콜백에서 발급된 client ID(`oaiapp_…`)를 저장하고 이후 로그인과 갱신에 씁니다. 로그아웃 뒤에도 client ID 대응과 호스트 ID는 지우지 않습니다.
- **인가.** 시스템 브라우저로 `https://auth.openai.com/api/accounts/authorize`를 엽니다. `response_type=code`, PKCE(`S256`, 패딩 없는 base64url `code_challenge`), 시도마다 새 `state`·`nonce`·verifier, 콜백은 `http://127.0.0.1:<port>/auth/callback`(localhost가 아닌 127.0.0.1, 바뀌는 것은 포트뿐, 리스너를 먼저 연 뒤 브라우저). 범위는 `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, `resource=https://api.openai.com/v1`. 계정 전환에는 선택 값 `id_token_hint`·`login_hint`를 씁니다. 동의를 다시 받을 때는 `prompt=consent`; `force_reconsent=true`는 OpenAI가 이 앱에 적용을 확인해 준 뒤에만.
- **토큰 교환.** `https://auth.openai.com/api/accounts/oauth/token`에 form 인코딩으로 `authorization_code` 교환(`resource` 포함). ID 토큰의 서명·발급자·대상(발급 client ID)·만료·nonce를 확인하고 `sub`를 계정 식별자로 씁니다. 응답의 granted scope에 `chatgpt.tokens.use.direct`가 없으면 로그인은 유지하되 플랜 사용은 꺼진 상태로 두고 추론하지 않습니다. 사용자가 플랜 사용을 거절해도 로그인은 유지하고 API 키 방식을 안내합니다.
- **수명과 갱신.** 접근 토큰 1시간(`expires_in: 3600`), 갱신 토큰 30일(갱신할 때마다 교체). 만료 전에 `grant_type=refresh_token`으로 갱신하고(`resource` 포함, `scope`는 보내지 않음), 같은 세션의 갱신은 하나씩 직렬화합니다(교체되는 토큰 경합 방지). 토큰 응답의 `earliest_refresh_at`은 문서에 필드만 있고 뜻은 설명되지 않았습니다.
- **호출.** `POST https://api.openai.com/v1/responses`, `Authorization: Bearer <access_token>`, `store: false`, `stream: true`, `response.completed`가 와야 성공. system 메시지 대신 `instructions`/developer 메시지(`role:"system"` 항목은 거절됨), HTTP에서는 `previous_response_id`를 쓰지 않습니다. 보낼 수 없는 값: `background`, `conversation`, `max_output_tokens`, `max_tool_calls`, `metadata`, `moderation`, `multi_agent`, `prompt`, `prompt_cache_retention`, `safety_identifier`, `temperature`, `top_logprobs`, `top_p`, `truncation`, `user`. 함수·사용자 정의 도구는 namespace로 묶거나 `additional_tools` 입력 항목으로 넣습니다. 웹 검색은 모델·정책에 따라 되고, 이미지 생성·파일 검색·Code Interpreter·컴퓨터 사용·호스팅 MCP/커넥터·`tool_search`·`programmatic_tool_calling`은 안 됩니다. 이미지·파일 입력은 고른 모델이 받을 때만 되고, 오디오·영상·음성 받아쓰기는 안 됩니다. Files API와 ChatGPT `backend-api`는 쓰지 않습니다.
- **모델 선택.** `GET https://api.openai.com/v1/models`의 `models` 중 `visibility == "list"`의 `slug`/`display_name`을 보여 줍니다. 계정을 바꾸면 다시 읽습니다. 목록은 권한 확인이 아니며, 실제 완료된 응답이 접근을 확인합니다.
- **한도.** 사용 한도는 스트림 중 `response.failed`의 `subscription_sharing_usage_limit_exceeded`(429) 등으로 옵니다. ChatGPT Plus의 5시간 한도는 이 플랜을 쓰는 모든 앱이 함께 쓰고(Pro는 5시간 한도 제외), 앱별 한도가 따로 있을 수 있습니다. 한도에 걸리면 새 요청을 멈추고 "Manage usage"(`https://chatgpt.com/settings/usage`) 링크를 주 행동으로 보여 줍니다. 초기화 시각을 추측하지 않습니다.
- **로그아웃·권한 철회.** 로그아웃은 요청을 멈추고 `https://auth.openai.com/.well-known/openid-configuration`의 `revocation_endpoint`에 갱신 토큰 폐기(`token_type_hint=refresh_token`, `client_id`)를 보낸 뒤 토큰을 지웁니다. 빈 200 응답이 성공이며, 원격 폐기를 확인하지 못하면 "이 컴퓨터에서는 지웠지만 원격 폐기는 확인되지 않음"을 알립니다. 사용자는 ChatGPT 설정에서 이 앱 연결을 끊을 수 있고 OpenAI는 앱에 알려 주지 않습니다. `subscription_sharing_invalid_user`(401)는 곧바로 철회로 보지 않고 요청 ID를 남겨 원인을 확인하며, 다시 로그인 안내는 철회가 확인됐거나 갱신이 끝내 실패했을 때만 합니다(2026-10-23 재확인으로 고침: 이전 판은 401을 바로 철회로 처리).
- **오류.** 범위 없음(403 `chatpass_v2_scope_not_authorized`), 권한 맥락 오류(403 `chatpass_v2_invalid_authorization_context`), 자격 없음(403 `subscription_sharing_user_not_eligible`), 지원 안 하는 경로(403 `subscription_sharing_route_not_supported`), 지원 안 하는 입력·도구·모델(400 `subscription_sharing_unsupported_capability`), 일시 불가(503 `subscription_sharing_usage_unavailable`·`subscription_sharing_user_unavailable`, 제한된 재시도), 스트림 전 코드 없는 401/403/503(403은 이용 지역일 수 있음), 갱신 오류(`invalid_refresh_token`, `token_expired`, `refresh_token_expired`, `refresh_token_invalidated`, `refresh_token_reused`, `invalid_client`)는 문서의 복구 방식을 따르고, HTTP 상태·응답 형태·오류 코드·요청 ID를 기술 상세에 남깁니다.
- **표기.** 로그인 버튼은 "Continue with ChatGPT". 처음 플랜 사용이 켜질 때 한 번 "You're using your ChatGPT plan"/"Got it"(한국어 화면은 같은 뜻으로)을 알리고, 도우미 입력창 옆에 "Using ChatGPT plan · Manage usage"(ChatGPT 플랜 사용 중 · 사용량 관리), 한도에 걸리면 "Usage limit reached"를 둡니다.

### 4.4 토큰 보호와 최소 전송

- **보관 위치.** 토큰은 Electron 주 프로세스만 다룹니다. 렌더러(화면)·백엔드·로그·프로젝트 파일·브라우저 저장소에는 들어가지 않습니다(지금 공유 서버 세션 토큰을 주 프로세스가 붙이는 방식과 같은 원칙). 디스크에는 OS 보호 저장소(macOS 키체인/Windows DPAPI, Electron `safeStorage`)로 암호화한 파일을 소유자 전용 권한(`0600`)으로 원자적으로 씁니다. 계정마다 client ID·토큰을 따로 둡니다.
- **URL·로그 금지.** 토큰은 URL에 넣지 않고, `id_token_hint`가 들어간 인가 URL은 기록에서 가립니다.
- **화면의 외부 접속 좁히기.** 지금 화면(`index.html`)의 CSP는 `connect-src`와 `img-src`에 `https:`(접속은 `wss:`도)를 통째로 허용해, 화면 코드가 아무 외부 주소로나 요청할 수 있습니다. 도우미를 넣기 전에 화면의 외부 접속을 앱이 실제로 쓰는 주소로 좁히고, `api.openai.com`·`auth.openai.com` 호출은 주 프로세스에서만 합니다(3단계의 선행 조건). **반영(2026-10-23).** 화면이 실제로 닿는 곳은 자기 페이지, 이 컴퓨터의 백엔드(루프백 HTTP/WS, 포트는 실행마다 바뀜), 데스크톱 앱에서만 사람이 실행 중에 고르는 공유 서버(HTTPS/WSS) 셋입니다. 브라우저(데스크톱 연결 없음)에서는 페이지가 두 번째 CSP를 넣어 HTTPS/WSS를 자기 출처로만 좁힙니다(브라우저 세션은 같은 출처만 씀). 데스크톱의 고정 CSP는 공유 서버 주소를 미리 알 수 없어 `https:`/`wss:`를 남기고, 주 프로세스가 연결된 공유 서버의 `/api`·`/ws` 말고는 화면의 HTTPS/WSS 요청을 모두 취소합니다(공급자 주소 포함, 테스트로 고정). 공급자 호출은 주 프로세스의 Node `fetch`로만 하고(리디렉션 거절), 화면의 도우미 코드에는 네트워크 호출·브라우저 저장소가 없습니다. 데스크톱 CSP에서도 `https:`/`wss:`를 빼려면 공유 서버 연결 뒤 화면을 다시 불러오며 그 주소를 CSP에 넣거나(앱 시작 시 공유 연결 복원이 먼저 필요), 공유 서버 통신을 주 프로세스로 옮겨야 합니다(남은 일).
- **보내는 내용 최소화.** 기본으로 보내는 것은 화면 단계, 상태·막힌 이유 문구, 오류 코드·메시지, 수치 요약(이미지 수, 클래스별 수, 정확도)입니다. 이미지 픽셀, 원본 경로 전체, 사용자 이름, 서버 주소는 보내지 않습니다. 경로는 파일 이름이나 상대 경로로 줄입니다. 이미지를 보여 주며 묻는 기능은 요청마다 "이 이미지 1장을 ChatGPT로 보냅니다" 확인 뒤에만 보냅니다(모델이 이미지를 받을 때만). 구현: 화면은 하단 안내의 그림(`currentAssistContext()`)에서 `scope`(프로젝트·원본 폴더 경로)를 빼고 수와 상태만 보내며(`services/assistantContext.ts`), 주 프로세스가 나가는 모든 글에서 경로를 파일 이름으로, 주소·이메일·키 모양을 가림 글자로 한 번 더 바꿉니다(`redact.ts`). 이미지 질문은 미리보기 확인 → 주 프로세스가 공급자 이름을 담은 확인 문구와 1회용 허가(2분) 발급 → 사람이 "이미지 1장 보내기"를 누른 뒤에만 1024px 사본을 읽어 보내며, 도구 없이 한 번만 호출합니다. 모델이 이미지를 받는다고 설정에 표시하지 않았으면 허가가 나오지 않습니다. 긴 대화는 최근 질문 단위만 남기고 앞의 질문은 한 줄 요약으로 줄입니다(추가 호출 없음).
- **서버 상태 없음.** `store:false`라 매 요청에 필요한 맥락을 다시 보냅니다. 대화가 길어지면 요약해 보내 한도 소모를 줄입니다.

### 4.6 실행 기록

도우미 대화와 도구 실행은 프로젝트 아래 로컬 기록(JSON Lines)에 남깁니다: 시각, 도구 이름, 인자 요약과 해시, 사용자가 확인했는지, 결과(성공·거절·오류 코드), 기존 감사 기록과의 연결(예: 클래스 지정의 `class_changed` 이벤트). 토큰·이미지·전체 경로는 남기지 않습니다. 사용자는 기록을 보고 지울 수 있습니다(지우기는 휴지통·보관 폴더 이동). 지금 공유 서버는 모든 `actor`를 로그인 사용자로 덮어쓰므로, 도우미가 부른 쓰기는 장부에서 사용자 본인 행동과 구별되지 않습니다. 도우미 도구 호출에는 실행 ID 헤더를 붙여 백엔드 감사 이벤트에 `via: assistant`와 실행 ID를 함께 남기도록 바꿉니다(권한은 그대로 사용자 역할).

구현(2026-10-23): 기록은 `<project>/assistant/runs.jsonl`(한 줄에 시각·실행한 사람·도구·등급·인자 요약과 sha256·사람 확인 여부·결과와 오류 코드·실행 ID·만든 기록 연결(`class_changed`, `job:…`, `batch:…`)), 경로·주소·이메일·키 모양이 든 요약은 백엔드가 거절합니다. 패널의 "기록 비우기"는 파일을 `assistant/archive/`로 옮기며 지우지 않습니다(4 MB를 넘어도 같은 곳으로 옮김). 확인된 쓰기 도구가 실행되는 동안 주 프로세스가 그 도구의 요청 하나(같은 메서드·경로, 로컬 백엔드나 연결된 공유 서버, 최대 2분)에 `X-Modu-Assistant-Run`을 붙이고, 백엔드 `ProjectContextMiddleware`가 요청 동안 이를 묶어 이미지 메타데이터 장부(`dataset_metadata._event`, 예: `class_changed`)와 작업 장부(`job_store` 이벤트, 예: 학습 `submit`)에 `via: "assistant"`와 `assistant_run`을 남깁니다. 새 미들웨어 대신 기존 미들웨어에 넣은 것은 원본 미들웨어 구성 검사(`original_current_project_request`)가 모르는 미들웨어를 거부하기 때문입니다. 공유 서버에서 이 기록 경로는 별도 역할 규칙이 없어 쓰기는 프로젝트 소유자만 됩니다(읽기는 구성원 모두; 다른 역할 허용은 남은 결정).

### 4.7 사용자가 직접 해야 하는 것

- (1차) 자기 API 키 입력·교체·삭제, 공급자와 모델 고르기, 이미지 전송 확인, 쓰기 도구 실행 확인.
- (2차, 확인 뒤) ChatGPT 계정 로그인과 "이 앱이 내 ChatGPT 플랜을 쓰는 것" 동의(브라우저에서 사용자가 직접), 플랜 사용 켜기·끄기, 연결 끊기(앱의 로그아웃 또는 ChatGPT 설정).

ChatGPT 로그인은 아직 실제 연결을 시험하지 않았고 약관 허용 여부도 확인되지 않았습니다. 이 문서는 연결이 된다고 주장하지 않습니다.

## 5. 쉬운 사용: 설계 방향 (최우선 축, 2026-10-22 합의)

**한 줄 원칙.** 화면을 새로 만드는 것이 아니라, **어느 화면에서든 사용자가 결정할 것이 하나만 남게** 만듭니다. 목표 사용자는 현장에서 처음 검사 프로그램을 쓰는 비개발자이고, 통과 기준은 2장 6번의 수치(첫 검사 흐름 저장까지 30분 이내·필수 클릭 40회 이내·막힘마다 한국어 이유와 해결 행동 하나)입니다. 2026-10-22 기준 측정 전이며 첫 실측값이 기준선입니다.

### 5.1 일곱 가지 방향

1. **결정 지점을 하나로.** 하단 상태 카드(상태 · 막힌 이유 → 해결 행동 · 왜 그런가요?)가 모든 단계의 유일한 안내자입니다. 화면의 나머지는 작업 공간입니다. 3~6단계도 2단계처럼 "지금 할 일 하나 + 진행 숫자 하나"를 갖고, 카드는 스스로 갱신됩니다.
2. **처음 30분의 길을 고정 — 첫 프로젝트 경로.** 폴더 열기 → 구조 자동 인식·작업 종류 제안 → 분할 추천값 저장 → 라벨 20장(직접 또는 SAM2 클릭) → 추천 설정으로 학습 → 결과 카드 → 흐름 템플릿에서 저장·평가 → 검사 시작. 모든 설정에 기본값이 있고 첫 사용자는 값을 고르지 않습니다. 처음 시작 안내와 예제 프로젝트를 이 순서와 똑같이 맞춥니다. 30분·40클릭은 이 경로에서 잽니다.
3. **세 겹의 노출.** 첫 사용자 기본은 간단히 보기(단계마다 주 행동·진행 숫자·작업 공간만). 전문가 기능은 지우지 않고 모두 보기와 기술 상세로 내려갑니다(키보드·화면 읽기 접근 유지).
4. **숫자를 사람 말로.** mAP·loss·threshold는 기술 상세에만. 화면에는 "이미지 54장 · 라벨 48장", "초안 6장 검토 대기", "학습 34/60회", "정확도 95% 안팎 · 놓친 불량 2장 · 잘못 잡은 정상 3장"처럼 행동과 이어지는 숫자만. 모델별 채택률도 같은 뜻의 숫자입니다.
5. **막힘은 이유 + 다음 행동 하나, 전부 한국어.** 사용자 화면에 닿는 모든 거절은 "왜 안 되는지 + 지금 할 수 있는 일"의 한 쌍. 서버의 영어 문구는 일괄로 걸러서 바꿉니다. 될 수 없는 버튼은 미리 끄고 옆에 이유를 둡니다(오류를 보여 주기보다 오류가 나지 않게).
6. **기본이 안전.** 기계가 만든 것은 초안, 사람이 채택해야 라벨. 쓰기는 자동 백업과 되돌리기가 붙고, 되돌릴 수 없는 것만 확인창. 영구 삭제 없음. 인터넷이 없어도 1~6단계는 그대로.
7. **배치와 글꼴은 흔들리지 않게.** 한글 포함 글꼴 번들로 OS마다 같은 줄바꿈, 1024px에서도 도구 줄은 한 줄·본문은 최소 높이, 보조 패널은 접힘이 기본.

하지 않을 것: 화면 전면 재설계, 전문가 기능 삭제, 도우미(챗봇)를 주 사용법으로 두는 것. 도우미는 위 경로를 대신 눌러 주는 보조입니다(4장).

### 5.2 원클릭 자동 진행

"처음부터 끝까지 자동 진행" 버튼 하나로 **사람이 꼭 필요한 지점까지** 달립니다. 새 엔진이 아니라 기존 단계(가져오기 → 분할 → 학습 → 평가 → 흐름 저장 → 검사)를 기본값으로 이어 붙인 것이며, 운영 주기가 이미 "라벨 → 학습 → 평가 → 승인 대기"를 혼자 잇는 방식과 같습니다.

- 사람이 꼭 필요한 지점은 둘입니다. ① 정답 라벨(검출·분할은 20장 정도를 사람이 그려야 함, 기계가 지어내지 않음) ② 승인·배포. 그 밖은 자동으로 지나갑니다.
- 결과: **분류**(폴더 이름이 곧 정답)는 폴더 하나로 검사 결과까지 원클릭. **검출·분할**은 원클릭 → 라벨 20장에서 멈춤(초안 검토 안내) → 다시 원클릭 → 결과.
- 안전: 자동으로 지나간 쓰기(분할 저장, 흐름 저장)도 백업과 되돌리기가 붙습니다. 승인·배포는 자동으로 하지 않습니다. 기본값(작업 종류 추정, 분할 비율, 프리셋·장치·가중치)은 시작 전에 한 줄로 보여 주고, 사용자가 바꿀 수 있습니다.
- 중간 실패: 어디서 멈췄고 무엇을 하면 되는지 상태 카드가 보여 주고, 다시 누르면 멈춘 곳부터 이어 갑니다(끝난 단계는 다시 하지 않음).
- 어려운 부분(솔직하게): 기본값을 안전하게 고르는 일, 수 분~수십 분 걸리는 학습의 실패 처리, 장치·가중치 준비(내려받기는 사용자 확인).

### 5.3 단계별로 사용자가 보는 것 (간단히 보기)

1. **이미지 준비(1단계).** 주 행동 "이미지 폴더 불러오기" → 학습 전 점검 → "분할 저장". 숫자: 이미지 N장 · 라벨 M장 · 학습/검증/시험.
2. **라벨 달기(2단계).** 모델이 없으면 "직접 라벨 달기"(분류는 클래스 고르기), 있으면 "초안 만들기 → 초안 검토". 숫자: 확정 M장 / 초안 N장 / 남은 K장, 모델별 채택률.
3. **학습(3단계).** 주 행동 "학습 시작"(모델·장치·가중치 준비됨을 한 줄로). 숫자: 진행 n/N회 · 남은 시간. 끝나면 "결과 보기".
4. **평가(4단계).** 결과 카드(정확도 범위 · 놓친 불량 · 잘못 잡은 정상) → "추천 기준 점수 적용", 틀린 이미지 보기.
5. **검사 흐름(5단계).** 템플릿에서 시작(모델 자동 연결) → "저장 · 평가" 한 번.
6. **검사(6단계).** "검사 시작" → 결과 표 · 내보내기. 현장 적용 조건은 접힘.

어느 단계든 "도우미에게 묻기"는 상태 카드 내용을 바탕으로 답합니다(4장). 도우미가 꺼져 있어도 모든 흐름은 그대로 됩니다.

### 5.4 지금 남은 간격과 순서 (2.5단계)

1. 3~6단계의 다음 행동·진행 숫자를 2단계와 같은 규칙으로(상태 카드 데이터 포함).
2. 사용자 화면에 닿는 4xx 거절 문구를 한 번에 훑어 한국어 이유+다음 행동으로(`test_beginner_errors_korean.py`의 범위 확대).
3. 배치 잔여: 브라우저 모드 '모두 보기' 1024px의 1단계 도구 줄 왼쪽 묶음, 2단계 보조 패널의 그림 영역 차지.
4. 처음 시작 안내·예제 프로젝트를 첫 프로젝트 경로와 같은 순서로.
5. 원클릭 자동 진행(5.2).
6. **디자인 정리(간단히 보기부터, 모두 보기는 그대로).** 2026-10-22 객관 평가: 기능 밀도는 높은데 시각 위계·여백·글자 크기·톤이 못 미쳐 "복잡한 전문가 도구"로 보임. 정리 항목 — (a) 머리글을 한 줄로(간단히 보기에서는 프로젝트·단계·보기 전환 정도만, 나머지는 더 보기 메뉴), (b) 글자 기본 13px 이상(11px은 설명 꼬리표에만), (c) 주 행동 버튼 스타일 하나·보조는 테두리/글자 버튼으로 통일, (d) 패널 안 설명 문단은 한 줄 + "자세히"로, (e) 한 화면 안의 밝은 영역/어두운 영역 톤 통일(2단계 위 패널과 캔버스, 1단계 사이드바와 본문), (f) 쌓이는 패널·겹치는 팝오버 정리. 기준 화면은 **27인치(2560×1440)**이며 1024px은 작은 창 보조 확인.
7. 실제 앱에서 첫 프로젝트 경로의 시간·클릭 수 측정 → PR 본문 기록 → 기준 미달 화면이 다음 작업. 화면 확인·스크린샷은 27인치 기준으로 봅니다.

필요한 공통 부품: 상태 카드 데이터(`currentAssistContext()`: 단계, 상태, 막힌 이유, 다음 행동, 진행 숫자, 패널 오류)를 렌더러 한곳에서 만들고 하단 안내·도우미·원클릭 진행이 함께 씁니다(1단계 작업으로 `src/renderer/stores/assistContext.ts`에 들어감).

## 9. 아직 확인하지 못한 것

- 실제 ChatGPT 계정으로 로그인·플랜 사용이 되는지, 그리고 이 앱이 받은 토큰으로 Responses API를 호출하는 것이 약관상 허용되는지(사용자 계정과 동의가 필요해 시험하지 않음). 확인 전까지 도우미는 API 키 방식만 구현합니다.
- "쉽다"의 통과 기준(30분·40클릭)은 아직 실측하지 않았습니다. 첫 실측이 기준선입니다.
- 계정별 사용 가능 모델과 이미지 입력 지원(문서: 모델이 받을 때만).
- 함수 도구를 namespace·`additional_tools`로 줄 때의 실제 동작.
- Plus·Pro 외 요금제의 자격(문서에 목록 없음), 계정·작업 공간 정책에 따른 제한.
- 공유 서버처럼 원격으로 여러 사용자에게 제공하는 형태는 문서상 별도 신청 대상이라 이번 범위에서 뺌.
- Linux에서 한글 대체 글꼴 때문에 문장이 얼마나 길어지는지는 직접 재지 않음(호스팅 CI 결과와 macOS 측정으로 추정).

플랜 호출·토큰 갱신/철회 실증 및 앱의 라이브 연결은 그 완료 전까지 지원한다고 표시하지 않는다.
사람 기준 시간/클릭 실증, 대표 현장 정답과 품질 승인, 실제 키/유료/이미지 전송 동의,
운영 배포는 여전히 별도 사용자 참여 항목이다. ux 모니터링은 중지 상태를 유지한다.

이 보완의 구체적 검사 범위와 실패/수정 기록은 [전체 설계 후속 QA](qa/2026-10-24-whole-design-followup.md)에 남긴다.

## 14. 사용자 후속 요청: ChatGPT 연결 준비와 실제 자료 진단 (2026-10-24)

사용자가 남은 구현을 계속하도록 지시하고 로컬·외장 자료를 사용하도록 지정했다.
이 절이 앞의 **라이브 코드 미구현** 및 **자료 위치 대기** 기록보다 최신 상태다.
실제 계정 로그인·약관 수락·플랜 호출·외부 이미지 전송을 대신 승인한 것으로 해석하지 않는다.

- `siwcStore.ts`와 `siwcConnection.ts`로 앱 자체의 보호 계정 저장·프로세스 독점 잠금,
  콜백 PKCE/검증·계정별 모델 선택·회전 갱신·SSE·로그아웃 경로를 만들고,
  `assistant` service/IPC/preload/설정 화면에 연결했다. 다른 앱의 자격 증명은 읽지 않는다.
- 화면에서 약관·전송/보관 안내를 확인하고 **Continue with ChatGPT**를 누른 뒤에만
  로그인 브라우저를 연다. 계정과 모델을 직접 고르며 플랜 scope가 없으면 질문을 보내지 않는다.
  모델 목록은 실제 호출 권한의 증거로 취급하지 않는다. 현재 ChatGPT 경로는 텍스트만 지원한다.
- 계정/모델 변경은 미리보기와 늦은 응답을 폐기한다. 저장소 오류가 나도 선택한 ChatGPT에서
  다른 API 공급자로 자동 전환하지 않는다. API 공급자는 사람이 직접 선택하면 독립적으로 쓸 수 있다.
- 정상 종료 중 회전 갱신이 진행 중이면 보관된 이전 토큰을 지운 뒤 저장소를 해제한다.
  지우기를 확인하지 못하면 잠금을 보존하여 오래된 토큰 재사용을 막는다. 비정상 종료 뒤
  남은 잠금은 자동 해제하지 않으며, 다른 프로세스의 종료와 재연결을 확인하는 복구가 필요하다.
- 가짜 토큰·가짜 HTTPS와 실제 로컬 콜백 수신기로 검증하며 실제 계정 성공과 분리한다.
  실제 계정의 scope·모델 호출·한도·갱신/철회와 OS별 보관은 여전히 사용자 참여 검증 대상이다.
- 로컬 실제 이미지 36장(고유 35장)과 기존 영역/분류 정답을 고정해 앱 엔진을 실행했다.
  문구 초안은 영역 49개에 대한 TP 0/FP 18/FN 49였고, 정상 12장에도 모두 후보가 있었다.
  정답 위치를 알려 준 SAM2도 평균 mask IoU 0.2788이었다. 이 조합을 현장 검사 모델로 승인하지 않는다.
  [조건·원본 보존·실패·한계](qa/2026-10-24-real-image-foundation-diagnostic.md)를 함께 기록한다.

실제 계정·현장 품질 승인·처음 사용자 시간/클릭·운영 배포는 구현 완료와 구분한다.
15분 모니터링은 재개하지 않는다. 기존 PR #10의 exact-head 회귀와 이 후속 코드 검증도 구분한다.

## 15. 원래 설계·Claude 인수인계 재대조: 공통 오류 연결 (2026-10-24)

사용자가 계속 구현하도록 지시한 뒤 원래 설계와 Claude의 인수인계 §4.2를 실제 코드와
다시 대조했다. 작은 창, SAM2 점 입력 후보, DICOM 환경 보완은 앞선 구현·기록을
재사용하며, 묶음 간 fingerprint 거절 정책도 유지한다. 최신 연결 코드와 진단은 §14를 따른다.

추가로 발견한 누락은 데이터 준비·문구 초안·모델 보조·학습·검사 실행 화면에 표시된
오류가 하단 공통 안내와 도우미의 오류 읽기에 전달되지 않는 것이었다. 기존 소유 등록과
정리 기능에 이 다섯 화면을 연결했다. 오류는 현재 프로젝트·원본·작업·라벨 세트에 속하며
모델 보조는 이미지와 열림 상태까지 구분한다. 서버 설정 오류는 같은 서버 연결에서는
유지하고 연결 전환 뒤의 이전 오류는 폐기한다. 학습 실패의 권장 행동도 오류 확인으로 바꿨다.
실행·채택·평가·배포를 자동 승인하지 않는다.

[집중 검사·실제 브라우저·검토에서 발견한 수정과 범위](qa/2026-10-24-common-panel-errors.md)를
기록한다. 이 보완의 exact-head 원격 CI와 병합은 별도로 확인한다. 사용자의 실제 로그인·
키/유료 사용·이미지 전송 동의, 처음 쓰는 사람의 시간·클릭 측정, 현장 품질 승인은
여전히 구현 완료와 구분하며 15분 모니터링은 중지 상태로 유지한다.

## 16. 원래 세 가지 방향의 구현 마무리 (2026-10-24)

사용자의 '3번까지 다 만들어' 요청에 따라 1) 쉬운 사용, 2) 라벨링 병목 완화,
3) ChatGPT 구독 계정 기반 내장 도우미를 다시 대조했다. 이 절이 앞선 연결 복구·플랜
재동의·최초 안내·한도 처리의 미완료 표시보다 최신이다.

- 로그인만 허용한 계정의 명시적 플랜 재동의, 계정별 최초 안내 확인 영구 보관,
  한도 도달 시 요청 중단·사용량 관리·명시적 재개를 구현했다. 재개는 질문을 자동 전송하지 않는다.
- 앱의 독점 실행과 종료된 PID를 확인할 수 있는 새 잠금만 명시적으로 복구한다.
  암호화 백업 후 불확실한 로그인 정보를 지우며 등록·모델·로컬 안내/중단 상태는 보존한다.
  살아 있거나 확인할 수 없는 소유자·옛 nonce 잠금은 자동 해제하지 않는다.
- 데이터 관리/내보내기의 주요 거절을 한국어 이유+다음 행동으로 보완했고,
  도우미 진단은 안전한 코드·입력 위치·실제 HTTP 상태만 남긴다.
- 실제 main·IPC·preload·renderer·backend를 잇는 Electron 통합 검사를 통과했다.
  생성 토큰/모의 HTTPS/모의 키체인 조건이며 실제 사용자 계정 호출은 아니다.
- 라벨 20장→초안 50장→명시 검토/백업→새 라벨 70장과 올바른 부모 모델의 재학습 요청을
  실제 저장소/라우트로 검증했다. 추론·학습 워커는 제어한 fixture라 학습 품질 개선의 근거는 아니다.

자세한 [검사·실패 수정·외부 수락 경계](qa/2026-10-24-priority-three-completion.md)를 기록했다.
실제 계정 로그인·약관 동의·플랜 실사용, 외부 이미지 전송 동의, 현장 정답/품질 및 처음 사용자
시간·클릭 실증은 여전히 사람의 참여가 필요하다. 이번 코드의 exact-head CI/병합도 별도 확인하며
15분 자동화는 재개하지 않는다.
