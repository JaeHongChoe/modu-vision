# 실제 localhost 브라우저 검증 · 2026-10-26

macOS의 소스 설치 환경에서 제품 실행기 `node scripts/local-web.cjs`
(`npm run web`의 실제 실행 대상)를 사용했습니다. 프록시·네이티브 브리지·storage 또는
온보딩 주입 없이 현재 renderer와 HTTPS API/WSS가 같은 origin에서 동작했습니다.
원시 계정·로그·데이터는 계획의 비공개 작업 폴더에 보존했습니다.
[해시·ID·프로브·실패 이력 JSON](2026-10-26-local-browser.json)이 상세 근거입니다.

## 실패 이력과 검증 범위

학습 전 검증 도구의 Host 상태값 기대, 중복 메뉴 선택자, ZIP helper의 module interop을
수정했습니다. 첫 프로젝트 생성 후 서버 설정이 갱신되지 않는 제품 결함도 발견해
별도로 수정·리뷰했습니다. 이전 루트에는 실제 학습 POST나 모델 파일이 없었음을 확인했고,
그 루트와 미전송 intent를 보존한 채 승인된 새 첫 실행 fixture에서 생성→학습을 검증했습니다.

최초 학습 후 단계 이동만으로 평가 GET이 발생한다고 가정한 검사는 시간 초과했습니다.
같은 저장 작업을 작업 센터에서 명시적으로 열어 평가를 완료했습니다. 이어 최초 같은 포트
재시작은 TIME_WAIT 재바인딩 문제로 실패했습니다. 별도 리뷰한 `SO_REUSEADDR` 수정 뒤
같은 작업·평가로 재시도해 즉시 재시작과 재연결이 통과했습니다. 모델은 다시 실행하지
않았습니다. 따라서 생성→학습의 연속 성공과, 서버 재실행 뒤 저장 모델 평가·재연결 성공을
구분합니다.

새 guard의 RED 기록과 focused **14/14** 통과를 남겼습니다. 전체 scripts 검사는
**162/166** 통과했습니다. 실패 4개 중 license 3개는 macOS 임시 경로의 symlink 제한으로,
정규 경로의 격리 TMPDIR에서 해당 파일 **8/8** 통과했습니다. 나머지는 기존
release-candidate health 오류 문구와 정규식의 불일치입니다. 관련 파일은 이 작업의
기준 소스와 같으며, 전체 suite가 통과했다고 표시하지 않습니다.

실제 흐름 확인 뒤 QA 도구의 정리 실패 처리와 `hardware_stats` 확인을 보강했습니다.
도구·실행기 단위 시험은 **20/20** 통과했으며, 이 보강 뒤 학습을 다시 실행하지
않았습니다. 최종 리뷰에서 발견한 상속 저장소 설정 문제는 `c91aac70`에서 웹 실행기에
한해 외부 폴더·S3 선택을 해제하는 방식으로 수정했습니다. 기본 저장 경로와 기존 파일은
그대로 유지합니다. 구현자가 보고한 관련 시험은 **167 통과·실제 서버 시험 3개 제외**이며,
루트도 새 설정 격리 4개 시험을 직접 실행해 통과를 확인했습니다. 독립 범위 재검토에서
남은 지적은 없었습니다. 이는 설정 격리 검증이며 위 실제 학습·평가·재접속 기록의
소스 HEAD나 저장 해시를 바꾸지 않습니다. 이 기능의 원격 CI·main 병합은 수행하지 않았습니다.

이 결과는 합성 데이터의 기능 검증입니다. 평가에서는 정상 1장을 맞히고 불량 1장을
놓쳤으므로 모델 품질·현장 수락 근거로 사용하지 않습니다. 격리 QA Chromium만 생성한
인증서를 허용했습니다. 실제 사용자의 최초 인증서 경고 처리, 설치 패키지, 네이티브 기능,
모든 브라우저, Windows/Linux 런타임은 승인하지 않았습니다. Windows는 현재 TLS 키 ACL
검사 미지원으로 실행할 수 없고 Linux 런타임은 검증하지 않았습니다.
