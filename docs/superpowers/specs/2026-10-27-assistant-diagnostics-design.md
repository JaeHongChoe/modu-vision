# 상태와 오류를 이해하는 도우미 실행기

## 사용자 의도와 선택

사용자는 GPT가 현재 프로젝트·화면·실행 상황과 발생한 오류를 실제로 확인한 뒤 작업을 돕기를 원한다. MCP, CLI 등 연결 방식은 맡겼다. 이번 변경은 기존 ChatGPT 계정 연결과 앱 명령 실행기에 관측 경로를 보강한다. 사용자에게 연결 방식 선택이나 기존 승인 범위를 다시 묻지 않는다.

## 현재 확인한 누락

- 기본 문맥은 하단 안내와 이미지 수 중심이다. 화면을 떠난 학습·평가·계산 서버 오류가 빠진다.
- `read_task_status`는 단계 상태만 반환하며 저장 영수증, 현재 단계, 수정 번호, 컨트롤러 오류가 빠진다.
- 학습 작업 재확인에서 원래 오류를 일반적인 중단 문장으로 바꾼다.
- HTTP/빈 JSON/전송 실패는 화면이 사라지거나 오류가 교체되면 도우미가 확인하기 어렵다.
- 질문의 문맥은 재생 호환성을 위해 고정된다. 같은 질문 안에서는 별도 읽기 도구로 최신 상태를 다시 확인해야 한다.

## 접근 방식

1. 기존 함수 도구에 앱 진단 읽기를 추가한다(선택). 기존 권한·웹/데스크톱 브리지를 재사용하며 별도 포트·인증·도구 서버가 필요 없다.
2. MCP 서버를 새로 노출한다. 여러 외부 에이전트와 연결할 때 유용하지만 이번 내부 도우미에 필요한 상태·오류 정보의 정확성을 저절로 해결하지 않는다.
3. 범용 CLI 실행기로 옮긴다. 프로세스 수명과 개발 자동화에는 이점이 있으나 앱 상태 계약과 저장 결과 확인은 여전히 별도로 필요하다.

방식은 사용자가 위임했으며 1번은 구현 판단이다. 진단 계약은 순수 DTO로 분리해 나중에 다른 전송 방식에서도 재사용할 수 있게 한다.

## 구현 계약

### 현재 관측과 오류 이력

- 질문 시점에 앱 진단 요약과 현재 작업 결과를 기존 문맥에 포함한다. 추측 대신 관측 시점·범위·확인 한계를 명시한다.
- `read_app_diagnostics` 읽기 도구가 프로젝트/자료/학습/평가/검사 흐름/검사 실행/계산 위치/최근 요청 오류를 선택해 다시 읽는다. 진단 읽기는 모델·학습·평가·연결 검사를 시작하지 않는다.
- 스토어의 현재 오류와 과거 요청 실패를 구분한다. 오류가 없다는 것은 수집 범위에서 없다는 뜻이며 전체 서버 로그의 무결함 증거가 아니다.
- 요청 실패 이력은 메모리에만 최대 40건, 같은 계정·프로젝트·연결 문맥에서만 읽는다. 요청 경로는 등록된 작업 이름으로 치환한다. 요청 본문·헤더·쿠키·토큰·응답 원문은 저장하지 않는다. 이전 문맥에서 늦게 끝난 요청은 현재 진단에 섞지 않는다.
- HTTP 상태, 오류 종류(HTTP/전송/JSON/문맥), 정제한 코드·설명, 발생 시점을 보존한다. 오류를 삼키거나 원래 throw 계약을 바꾸지 않는다.
- 도구 결과는 유효한 JSON을 유지하며 4,000자 전송 한도보다 작게 만든다. 목록이 길면 생략 수와 offset/next_offset을 제공해 나머지 오류·작업도 읽을 수 있게 한다. 크기 제한으로 항목이 줄어도 실제 반환한 수만큼만 다음 offset을 진행한다.

### 실행 결과 피드백

- 현재 작업의 revision/status/current step/연결 일치/컨트롤러 오류와 단계별 상태를 읽는다.
- 원시 receipt/args/binding/계정 키/actor/workspace/경로/해시를 그대로 전달하지 않는다. 허용한 job/batch/run/version/evaluation 식별자, 실행 상태와 완료 검증 수치만 내보낸다.
- 프로젝트나 계정 문맥이 다른 기록은 실행 증거를 제공하지 않는다. 원장 갱신 시점과 현재 관측을 구분한다.
- 대기 중 학습을 읽을 때 완료·실패·취소 상태 및 정제한 오류를 영수증에 남긴다. 시작됨을 완료나 품질 수락으로 표현하지 않는다.
- GPT는 오류를 진단할 때 최신 진단과 작업 번호·저장 결과를 먼저 읽는다. 불명확 실행을 재시도하거나 새 작업을 자동 시작하지 않는다. 수정 계획도 기존 사람 확인을 거친다.
- 질문/읽기 도구가 피드백을 전달한다. 폴링·복원·작업 완료 이벤트는 GPT를 자동 호출하지 않는다.

### 전송 경계

- 파일·이미지 픽셀·전체 모델 출력·임의 콘솔/서버 로그를 수집하지 않는다.
- 경로·주소·메일·SSH 사용자·자격증명은 진단 DTO 생성 시 정제하고 main의 기존 전송 정제를 다시 거친다. 텍스트는 비신뢰 자료로 표시하며 명령으로 취급하지 않는다.
- 도우미 인증 오류도 원래 오류 코드/복구 안내로 구분한다. 계정·모델 변경, 재로그인, 유료 요청, 외부 전송을 자동 실행하지 않는다.
- 기존 12개 행동, 승인·정답·초안 채택·배포 경계와 작업의 중복 실행 방지는 유지한다.

## 검증과 완료 기준

- 화면에 없는 오류, HTTP 409/500·빈 JSON·전송 실패, 작업 실패 원인, 진행 중/완료/불명확 결과 구분을 제어된 검사로 재현한다.
- A→B→A 프로젝트/계정 변경, 늦은 응답, 긴 오류/영수증, 민감 문자열/명령문 삽입, 24단계 작업을 회귀 검사한다.
- 새 질문 문맥 → 도구 조회 → 오류/작업 결과 → 모델의 후속 답변/수정 계획을 가짜 공급자로 연결 검증한다. 진단·폴링·복원 자체의 실제 공급자 호출은 0건이다.
- 타입·관련 회귀·빌드·필요한 source gate와 독립 리뷰를 통과한다. 실제 GPT 계정 end-to-end, 설치 앱 업데이트, 모델/현장 품질은 별도 근거가 필요하다.
- 기존 PR18/19/20 및 사용자 프로젝트·원본·설치 앱·실행 서비스는 보존한다. 새 변경은 PR20 위 기능 브랜치에 분리한다.
