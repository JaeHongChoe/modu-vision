# Localhost Browser Studio 실행 설계

상태: 사용자 로그인 방식 선택 및 상세 설계 승인 완료. “설계대로 진행”으로 구현 승인.
기준 소스: `c1bc995408a4a9b482db81f0225f1d1e973c0ac9`.

## 목적과 사용자 선택

사용자는 PC에서 Modu Vision을 실행한 뒤 localhost 주소를 일반 브라우저로
열어 업로드, 라벨 저장, 학습, 평가, 재접속을 사용하려고 한다.
클라우드 배포가 아니라 이 PC의 Python 엔진이 계산하고 이 PC에 저장한다.
사용자는 기존 HTTPS 로컬 계정 로그인 방식을 선택했다.

## 검토한 방식

1. **기존 HTTPS 계정 인증 + 전용 웹 실행기 (선택됨).** 기존 쿠키·CSRF·프로젝트
   권한을 유지한다. 로컬 인증서와 첫 계정 설정이 필요하다.
2. localhost 무로그인 게이트웨이. 테스트 하네스의 서버 측 토큰 주입을 참고할 수
   있으나, 제품용 Host/Origin/CSRF 경계와 연결 수명을 별도로 설계해야 한다.
   사용자는 1번을 선택했으므로 이번 작업에 포함하지 않는다.
3. 기존 Electron 실행 후 Vite 주소만 열기. 외부 브라우저에는 네이티브 창의
   API 권한이 없으므로 정상 실행 경로가 되지 않는다.

## 실행 경험

- 이미 설치한 소스 개발 환경에서 `npm run web`으로 현재 renderer를 빌드하고
  웹 엔진을 실행한다. Electron 창을 띄우지 않는다.
- 기본 주소는 `https://localhost:8443`이다. 포트는 명시적으로 변경할 수 있다.
  사용 중인 포트는 오류로 설명하고 종료하며, 다른 프로세스를 종료하지 않는다.
- 첫 실행은 터미널에서 계정 이름, 12자 이상의 비밀번호, 비밀번호 확인을 받는다.
  기존 AccountStore의 최초 관리자 생성 동작을 사용한다. 비밀번호는 화면·명령행
  인자·로그·평문 설정에 남기지 않는다. 계정이 있으면 다시 생성하지 않는다.
  비대화형 실행에서 초기 계정이 없으면 설정 방법을 안내하고 실패한다.
- 준비가 끝나 실제 HTTPS health 응답을 확인한 뒤 주소를 출력하고 기본 브라우저를
  연다. `--no-open`으로 자동 열기를 끌 수 있다. 페이지에서 기존 로그인과 프로젝트
  생성/선택 UI를 사용한다.
- 터미널의 Ctrl+C로 자신이 실행한 서버를 정상 종료한다. 새로고침/재실행 후에는
  기존 정책대로 다시 로그인하고 저장한 프로젝트와 작업을 연다.
  실행 중 학습의 종료 정책은 기존 엔진을 따른다. 서버 종료가 학습 강제 종료라고
  표시하지 않으며 기존 detach·작업 원장·자원 lease·재시작 복구를 우회하지 않는다.
- Node/Python 및 기존 requirements 설치는 사전 조건이다. 실행 중 임의 패키지 설치,
  시스템 서비스 등록, 외부 계정 연결, 모델 다운로드나 학습 자동 시작은 하지 않는다.

## 서버 구성

- 별도 Python 웹 진입점을 추가하고 기존 `backend.main.create_app`은 변경하지 않는다.
- 외부 ASGI dispatcher가 빌드된 renderer만 제공한다. `/api/`, `/health`, `/ws/`는
  경로와 요청 문맥을 그대로 기존 API 앱에 전달한다. backend lifespan도 그대로 전달한다.
  정적 파일은 로그인 전에 제공하되 API는 기존 인증을 통과해야 한다.
- Uvicorn이 직접 TLS를 처리한다. HTTP reverse proxy나 테스트 fixture를 제품 실행기로
  사용하지 않는다. `proxy_headers=False`로 전달 헤더가 요청 scheme/주소를 바꾸지 못한다.
- 소켓은 `127.0.0.1`에만 바인딩한다. 임의 host/LAN 바인딩 옵션을 제공하지 않는다.
  요청 Host는 설정된 localhost와 포트로 제한한다. API/WSS Origin도 정확한 현재
  HTTPS origin으로 고정한다. 별도 브라우저 포트 질의 인자는 사용하지 않는다.
- 정적 파일은 renderer 디렉터리 내부의 공개 빌드 파일에 한한다. 경로 이탈, 심볼릭
  링크를 통한 외부 파일, 저장 데이터·키·계정 DB·소스 파일은 제공하지 않는다.
  잘못된 경로와 메서드는 명시적으로 거절한다.
- 기존 Secure/HttpOnly/SameSite=Strict 쿠키, 변경 요청 CSRF, 계정·멤버십·프로젝트
  문맥은 유지한다. 프로세스 capability를 브라우저/URL/storage에 전달하지 않는다.
  네이티브 브리지나 테스트 shim을 주입하지 않는다.
- 웹소켓은 ASGI로 직접 기존 `/ws/`를 처리하므로 쿠키 및 Origin 인증을 유지한다.
  실제 로그인된 브라우저에서 WSS 연결과 재연결을 추가 확인한다.

## 인증서

- 기본은 웹 전용 데이터 폴더의 localhost 자체 서명 인증서와 개인 키를 생성·재사용한다.
  localhost SAN, 유효기간, 키 일치와 파일 권한을 검사한다. 잘못된 기존 파일을 덮어쓰지
  않고 교체 방법을 안내한다. 개인 키는 사용자만 읽을 수 있게 저장한다.
- 사용자가 지정한 인증서/키 쌍도 사용할 수 있다. 자동 CA 설치, OS 신뢰 저장소 변경,
  브라우저 인증서 검사 비활성화는 하지 않는다.
- 자체 서명 인증서의 첫 브라우저 경고와 신뢰 선택은 사용자가 직접 처리한다.
  안내문에 주소·인증서 위치·지문 확인 방법과 해당 로컬 서버라는 범위를 설명한다.
  QA의 인증서 허용 옵션은 격리된 시험에만 적용하며 일반 사용자 실행에 전달하지 않는다.

## 데이터와 기존 앱 보존

- 기본 웹 저장 루트는 OS별 사용자 전용 앱 데이터 디렉터리의 `Modu Vision Web`이다.
  명시적 `--data-dir`도 지원한다. Electron의 기존 userData 또는 repo/projects를
  자동 채택하지 않는다. 새 계정 DB를 기존 workspace에 조용히 연결하지 않는다.
- backend를 import하기 전에 프로젝트/계정, USER_DATA, split manifest, thumbnail cache,
  flow template 및 다른 발견된 전역 쓰기 경로를 웹 루트로 고정한다. 모델 파일은 기존
  입력·검증 정책을 따른다. 기존 가중치 캐시는 읽을 수 있지만 사용자 파일을 이동하지 않는다.
- 같은 웹 데이터 루트의 중복 실행은 잠금으로 거절한다. stale lock은 실제 소유를
  판단해 처리하며 PID만 보고 타인 프로세스를 종료하지 않는다.
  이 잠금은 웹 서버 인스턴스의 소유만 나타내며, detached worker의 쓰기 권한이나
  종료를 대신하지 않는다. 재실행 시 기존 작업 복구·동시 쓰기 가드를 그대로 따른다.
- 데스크톱과 웹의 저장 공간은 분리되지만 물리 GPU는 공유한다. 두 앱 사이 GPU 예약이
  통합됐다고 주장하지 않고 실행 안내에 동시 학습 자원 사용을 설명한다.
- primary main의 untracked `docs/handoff-to-codex.md`, 기존 QA·가이드·작업트리 자료는
  보존한다. 신규 개발은 격리 브랜치에서 수행한다.

## 확인할 결과

1. CLI 설정·대화형 최초 계정·재실행·중복 루트·포트 충돌·정상 종료와 준비 실패를 검증한다.
2. 정확한 Host, 위조 전달 헤더, 다른 Origin, 미인증 API, CSRF 없는 변경, 정적 경로 이탈,
   capability 비노출, 잘못된 인증서/키를 거절하는 테스트를 만든다.
3. 실제 제품 웹 실행기를 격리 데이터 루트로 시작한다. 테스트 전용 프록시를 쓰지 않고
   일반 renderer와 실제 HTTPS API를 통해 로그인·프로젝트 생성·ZIP 업로드·라벨 저장을 확인한다.
4. 합성 데이터와 기존 허용 로컬 가중치로 한 번의 작은 실제 학습·평가를 수행하고 저장된
   job/evaluation/label을 서버 재실행·새 브라우저 로그인 후 다시 읽는다. 기존 PR15 시험
   결과와 이번 제품 실행기 결과를 구별한다. 모델 품질·현장 수락으로 확대하지 않는다.
5. 같은 브라우저에서 실제 WSS telemetry 연결·재연결과 서버 종료를 확인한다.
6. 변경에 맞는 로컬 검사·독립 코드 리뷰를 완료한다. 현재 소스와 정확한 CI head의 근거를
   구분해 기록하며 기존 실패 이력을 지우지 않는다.

## 범위 밖과 구현자 판단

공개 호스팅, LAN 공유, 설치형 웹 패키지, 자동 OS 신뢰 등록, 데스크톱 전용 계정 도우미,
네이티브 폴더 선택·자동 업데이트, 실제 계정 로그인이나 유료 모델 호출은 이번 범위가 아니다.
파일 이름, 모듈 분리, 잠금 구현, 오류 표현 및 테스트 구성은 위 불변 조건 안에서 구현자가
정한다. 새 보안/저장 정책이 필요해지면 이를 조용히 확대하지 않고 설계를 갱신한다.
