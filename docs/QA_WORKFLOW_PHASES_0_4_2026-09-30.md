# Phase 0~4 기능 QA 기록 · 2026-09-30

## 판정 범위

이번 기록은 제품 전체 기능의 검증이나 현장 적용 승인을 뜻하지 않는다. 아래 `확인`은 적힌 입력·실행 경로의 기능 확인이다. 단위·통합 테스트, API 실행, 네이티브 앱 클릭, 별도 서비스 프로세스 실행을 구분한다. 1 epoch 학습과 단일 이미지 판정은 정확도·재현율·과검률·지연시간 또는 양산 승인 근거가 아니다. 원본 88장에는 독립 검증된 OK 정답 코호트가 없어 실제 후보 모델 승격 조건을 충족했다고 볼 수 없다. 고객 파일명·경로·호스트·해시·비공개 자료는 이 문서에 적지 않는다.

## 이어서 수정한 5단계 플로우 오류

- 저장 중 recipe 또는 활성 버전 포인터 쓰기를 실패하도록 주입했다. 이전에는 API가 500을 반환한 뒤 실패한 새 버전이 목록에 남았고, 포인터 실패 때는 recipe와 활성 그래프도 달랐다. [저장 API](../backend/api/routes_flowchart.py)에 기존 파일 복구와 실패 버전 제거를 적용해 일반적인 쓰기 실패에서는 이전 버전·recipe·활성 그래프가 유지되도록 했다. 저장 도중 목록·활성화·내보내기·읽기 요청이 실패 버전을 보지 않도록 같은 프로세스의 잠금을 적용하고 동시 요청 회귀를 통과했다. 복구 쓰기 자체가 실패하면 활성 포인터가 가리키거나 recipe에 남은 새 버전을 지우지 않고 복구 미완료를 응답에 표시한다. 강제 종료, 다중 프로세스 공동 저장 및 실제 저장장치 장애에서의 완전한 원자성은 검증하지 않았다.
- 연결되지 않은 순환 그래프의 오류에서 `문제 노드 보기`가 잘못 입력 노드를 선택하는 경우를 재현했다. [편집기 검증](../src/renderer/components/flowchart/flowchartGraph.ts)이 방문하지 못한 실제 노드를 가리키도록 고쳤고 [Node 회귀](../src/renderer/components/flowchart/flowchartAggregate.test.cjs)가 통과했다. 현재 빌드를 다시 연 네이티브 앱에서 저장된 5모델 플로우에 검사 노드 2개를 추가하고 서로 연결해 순환 오류를 만들었다. 정상 입력 노드를 선택한 뒤 `문제 노드 보기`를 눌러 실제 순환의 `검사 모델 6`이 선택됨을 확인했다. Undo 4회로 테스트 편집을 모두 되돌려 기존 저장 버전·모델 5/5 연결 상태로 복귀했으며 테스트 그래프는 저장하지 않았다.

## 연결이 끊긴 뒤 이어서 수행한 복원·단계 이동 QA

### 수정한 문제

- 복원 데이터가 프로젝트 안에 있다는 이유로 재백업이 422를 반환했다. 소스를 `source/`에 한 번만 넣고 프로젝트 파일 목록에서는 해당 소스 하위 경로를 제외한다. 재백업→두 번째 새 위치 복원에서 이미지·체크포인트 바이트와 모델 사전 검증을 확인했다.
- 복원 시 source 경로는 바뀌지만 source 키가 들어간 recipe 파일명은 그대로였다. source 기반 recipe 조회가 모델 없는 기본 템플릿을 반환하는 경우를 재현하고 파일명 재연결을 추가했다.
- 복원 프로젝트에서 다른 데이터 폴더로 바꾼 뒤 다시 백업·복원하면 이전 source와 현재 source가 같은 폴더로 합쳐졌다. 겹치지 않는 복원 소스 폴더를 선택하고 추출 목적지 충돌을 거절한다. 이전·현재 source의 파일 목록과 같은 이름의 이미지, 고객 JSON 바이트가 각각 유지되는 회귀를 통과했다.
- B 레이블셋 활성 상태의 백업은 비활성 기본 세트에서 학습한 유효 모델의 지문을 재연결하지 못했다. 새 백업은 등록된 레이블셋별 현재 지문을 기록하고 정확히 일치하는 기록만 복원 경로에 맞게 바꾼다. 학습 후 라벨이 바뀐 오래된 모델과 다른 레이블셋 모델은 계속 거절하며, 기존 v1 백업의 활성 세트 복원도 유지한다.
- 복원 프로젝트와 원래 프로젝트가 같은 job ID를 쓰면 메모리의 원래 작업이 복원 모델을 가렸다. 선택한 프로젝트의 완료 체크포인트·receipt를 우선한다. 현재 프로젝트의 진행 중 작업은 계속 차단하고 다른 프로젝트의 동일 ID 상태는 복원 모델에 적용하지 않는다.
- 같은 source를 쓰는 프로젝트·레이블셋 전환 후 import 이력이 남아 기존 모델 평가 조회를 막았다. 문맥이 바뀔 때만 이력을 초기화하며 출처·작업·지문 검증으로 복구한다. 라벨 편집 후 같은 문맥의 모델 복구 차단은 유지한다. 지연된 레이블셋 목록·오류·완료 응답도 현재 문맥만 갱신한다.
- source 경로에 끝 슬래시·부모 경로·심볼릭 링크 표기가 있으면 이력·검토 큐가 0건으로 보였다. 새 기록의 출처를 정규화하고 기존 행은 바꾸지 않은 채 현재 프로젝트 DB 안에서 같은 경로로 조회한다. 이력 응답에는 별도 정규화 경로를 제공하고, 화면의 자동 열기·수동 열기·재판정 후 새로고침도 이 값으로 비교해 목록에서 보인 기록을 실제로 열 수 있게 했다. 원래 경로와 그래프·모델 증거는 보존하며 프로젝트·작업 유형의 일치 조건도 유지한다.
- 그래프 좌표 `0.0`/`0` 표기 차이로 API·앱의 새 검사 해시가 달랐다. 새 검사 기록은 스키마 기본값과 유한한 정수형 숫자를 정규화한다. 저장 버전 목록도 같은 서버 헬퍼로 해시를 제공하며 앱은 이 값을 사용해 지수 표기의 차이도 피한다. `1e-7`·`1e-6`·큰 숫자의 저장 버전/새 검사 해시 일치와 이전 백엔드의 대체 계산을 회귀로 확인했다. 기존 기록의 JSON·해시와 변조 검증은 유지한다.
- 패치 분류의 `null` 픽셀·Blob 수치가 빈 값 또는 임의의 0으로 표시됐다. 실제 숫자만 카드·상세에 표시하고 실제 측정한 0은 유지한다. 분류·검출에 공통으로 쓰는 신뢰도 제목도 `모델 신뢰도`로 표시한다.

### 실제 입력과 관찰

- 기존 실제 출처 이미지 8장, 학습/검증/시험 4/2/2, 16개 라벨 패치, 서로 다른 완료 체크포인트 5개를 사용했다. 이번 복원 QA에서는 새 학습을 시작하지 않았다.
- 전체 프로젝트를 새 위치에 복원해 5모델 사전 검증·source 기반 recipe·활성 저장 버전 조회를 확인했다. source의 25개 파일과 모델 5개의 SHA-256이 원본·첫 복원·두 번째 복원에서 일치하며 원래 source와 체크포인트는 바뀌지 않았다.
- API로 전체 8장을 5단계와 6단계에 실행했다. 8/8 결과 비교가 통과했고 NG 8, 검사 오류 0이었다. CSV/JSON 8행의 저장 버전·그래프·모델·이미지 해시와 판정이 일치했다.
- 실제 시험 이미지로 전체 플로우 71파일 패키지를 만들고 앱 엔진/패키지 결과를 비교해 통과했다. 복원된 기존 패키지 5개도 무결성 검사를 통과했다. 백엔드를 새로 만들어 같은 프로젝트를 다시 열고 동일 이미지를 실행했으며 결과가 일치했다. 재백업→재복원 후 같은 이미지·모델 검증도 통과했다.
- 네이티브 최신 빌드에서 두 번 복원한 프로젝트를 열어 데이터 8장과 4/2/2 분할을 확인했다. 검수 레이블셋 복제본에 진단용 OK 주석을 저장하면 이전 모델 평가가 차단됐고, 기본 레이블셋으로 돌아오면 재학습 없이 기존 평가가 복구됐다. 진단용 주석은 독립 검증된 OK 정답으로 취급하지 않았다.
- 같은 앱에서 저장된 5모델 혼합 그래프를 열어 실제 시험 이미지 1장 검사→6단계 이동→전체 8장 일괄 검사를 진행했다. 저장 버전 연결을 유지하며 8/8 완료, NG 8, REVIEW·실패·미실행 0을 확인했다. 중간 모델 5개의 실행 기록을 확인했다.
- 네이티브 전체 플로우 내보내기에서 다른 시험 이미지로 모델 5개·파일 71개·최종 NG/ROI 1개·실제 이미지 결과 일치를 확인했다. CSV/JSON 저장 버튼으로 파일을 각각 내려받아 8행의 판정·버전·이미지·모델 해시를 파일에서 다시 비교했다.
- 화면 재로딩 후 5모델 연결을 복구하고 동일 시험 이미지를 다시 실행했다. 패치 결과 카드·상세에서 없는 픽셀·Blob 수치가 사라졌고 실제 판정·결함 점수·좌표는 유지됐다.
- 마지막으로 macOS arm64 패키지를 다시 만들고 패키지 안의 수정 백엔드 5개 파일·HTML·렌더러 번들이 소스 빌드와 바이트 단위로 일치함을 확인했다. 별도 QA 프로필의 패키지 앱에서 다시 복원본을 열어 기존 평가 복구→5모델 시험 이미지 검사→전체 8장 배치를 완료했다. 새 검사 기록·화면 카드·내보내기 화면의 그래프 해시가 일치했고 모델 5개의 파일 해시와 8장 전부의 노드 `passed` 기록을 DB에서 확인했다.
- 같은 최종 앱에서 실제 시험 이미지로 플로우 패키지를 새로 만들었다. 화면 집계는 **72파일**이며 무결성 목록의 **71파일+manifest 1개**, 모델 5개를 확인했다. 앱/독립 실행 패키지 결과는 NG/ROI 1개로 일치했다. CSV/JSON 저장 버튼을 다시 눌러 8행의 판정·이미지·그래프·모델·저장 버전을 파일에서 대조했다.
- 임시 복원본의 검사 기록 하나에 이전 형식의 경로 별칭을 넣어 네이티브 자동 표시→다른 이력 선택→별칭 이력 다시 열기를 확인했다. 원문 경로·그래프 해시는 유지됐다. 현재 경로와 기록 경로가 모두 다른 별칭인 조합은 Node 회귀로 확인했다. macOS 폴더 선택기는 입력 별칭을 실제 경로로 반환하므로 이 조합을 앱에서 강제로 만들었다고 주장하지 않는다.

고객 원본, 모델, 실제 경로·식별자·해시와 API 응답은 임시 QA 결과에만 보관하며 Git에는 코드와 검증 절차를 기록한다. 위 NG 8건은 기능 연결 증거이며 판정 품질 승인 근거가 아니다.
