# 실행과 검사 문제 해결

## 앱이나 백엔드가 시작되지 않을 때

- Windows에서는 `npm.cmd`와 `.venv\Scripts\python.exe`를 사용합니다. `python`이 Store 안내로 연결되거나 PowerShell 스크립트가 막히면 [Windows 실행 안내](quickstart-windows.md)의 직접 실행 명령을 확인하세요.
- Python 3.13과 OS에 맞는 CPU 잠금 파일을 사용합니다. 의존성 해시 검사가 실패하면 파일·환경을 확인하고, 해시 검사를 끄지 않습니다.
- 소스 실행에서는 `VISION_AI_PYTHON`이 해당 가상환경의 Python을 가리키는지 확인합니다. 패키지 실행은 일치하는 `backend_bin`과 체크섬 inventory가 필요합니다. [플랫폼 기준](release-platform-matrix.md)을 확인하세요.
- 브라우저 e2e에 Chromium이 없으면 설치된 Chrome 채널을 지정합니다. Electron 검사에는 잠금 파일에 맞는 Electron이 필요합니다.

## 모델·서버·검사 결과가 준비되지 않을 때

- 서버 연결 성공 뒤에도 GPU 사전 검사와 실제 작업 완료 기록을 확인합니다. SSH 연결만으로 CUDA 실행을 완료한 것으로 보지 않습니다.
- 작업이 대기 중이면 요청 장치, 자원 예약, 작업 원장의 최신 상태를 확인합니다. 다른 작업을 중단하거나 다른 GPU를 사용하기 전에 담당 범위를 확인하세요.
- 검사에는 완료된 모델, 고정된 데이터 버전, 검증한 플로우·패키지가 필요합니다. REVIEW·timeout·cancelled·입력 오류는 OK 승인이 아닙니다.
- 배치 입력의 중복 ID, 잘못된 필드, 입력 해시 불일치를 수정하고 새 결과 경로로 실행합니다. 입력 이미지는 실행 중 변경하지 않습니다. [배치 형식과 종료 코드](api-integration.md)를 확인하세요.
- C++·C# SDK에는 동일 아키텍처의 CPython 환경과 개발 헤더가 필요합니다. C#에는 .NET과 동일 C ABI 라이브러리도 필요합니다. 패키지 무결성 오류는 재검증·재내보내기로 해결하고 보호 검사를 끄지 않습니다.

## 문제 보고 자료 저장

앱의 **배포·운영 → 설치·진단 → 문제 보고 자료**에서 필요한 항목을 선택하고 **진단 자료 저장**을 누릅니다.
자료에는 버전·의존성, 패키지 ID, 장치 실행 상태, 오류 종류를 넣습니다. 원본 이미지는 넣지 않습니다.
알려진 인증 문자열, 개인 경로, URL과 사설 주소는 숨깁니다. 임의의 문자열에 들어 있는 모든 민감정보까지 보장하는 검사는 아니므로 공유 전에 내용을 확인하세요.
오류를 보고할 때 앱 버전, 소스 커밋, 실행 OS·장치, 재현 순서, 기대·실제 결과를 함께 적습니다.
취약점 상세와 비밀정보는 공개 이슈에 올리지 말고 [보안 안내](../SECURITY.md)를 따릅니다.

## 공개 후보의 정적 검사

검사할 Git 커밋과 선택한 산출물을 읽고 새 JSON 보고서를 만듭니다. 파일 수정, ZIP 추출, 명령 실행, 업로드를 하지 않습니다.
`--output`은 존재하지 않는 파일 경로여야 합니다. 부모 폴더는 미리 만듭니다.

```powershell
.venv\Scripts\python.exe scripts/publication_audit.py --revision HEAD --artifact support.json --output publication-review.json
```

`--since BASE`는 BASE 이후 커밋 메시지도 검사합니다. `--forbidden-term`을 반복하여 공개하면 안 되는 조직명 등을 지정할 수 있습니다.
기본 검사는 작업 폴더의 미커밋 변경 대신 지정한 Git 객체를 읽습니다. 후보 변경을 커밋한 뒤 해당 커밋으로 검사하세요.
알려진 인증값, 개인 경로·연락처·사설 주소, 데이터·모델 파일, 불투명 바이너리, 읽지 못한 파일을 검토 대상으로 기록합니다.
일치한 내용은 출력하지 않습니다. 파일별 8 MiB, 전체 128 MiB, 입력 10,000개를 넘으면 미검사 항목을 남깁니다.

종료 코드 0은 이 검사 범위의 통과, 1은 검토 필요, 2는 입력·보고서 경로 등의 거절입니다.
검출되지 않았다는 결과만으로 비밀정보 부재·라이선스·서명·배포 승인을 판단하지 않습니다.
필수 저작권·라이선스 고지는 보존합니다. 직접 검토한 비인증 항목만 정확한 `finding_id`와 사유로 허용할 수 있습니다.
내용·위치가 달라진 항목에는 기존 허용이 적용되지 않습니다. 인증값과 미검사·위험 경로 항목은 허용 목록으로 통과시킬 수 없습니다.

```json
{"schema":"PublicationAllowlist/v1","entries":[{"finding_id":"검토한 보고서의 64자리 소문자 SHA-256","reason":"보존해야 하는 라이선스 고지임을 직접 확인"}]}
```

허용 파일은 `--allowlist reviewed-findings.json`으로 지정합니다. 경로 전체를 허용하거나 자동으로 모든 항목을 허용하지 않습니다.
