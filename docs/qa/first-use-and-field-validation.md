# 사람 실사용·현장 품질 확인

자동 조작·합성 예제 통과와 별도로 기록한다. 기본 1~6단계는 도우미 연결 없이
사용할 수 있다. 모델·런타임이 준비된 환경에서는 인터넷 없이 실행한다. 실제 계정
요청은 이 시험의 필수가 아니며, 준비되지 않은 모델의 설치 시간은 아래 측정에 포함한다.

## 처음 쓰는 사람 시험

- 참가자: 개발·QA에 참여하지 않은 사용 경험 없는 사람. 관찰자가 대신 누르지
  않는다. 설명이 필요했던 지점과 설명에 쓴 시간도 기록한다.
- 자료: 보존된 24장 검출 예제의 새 복사본과, 사용자가 고른 실제 폴더의 별도
  복사본을 각각 사용한다. 원본, 확정 정답과 사용 중 프로젝트에는 쓰지 않는다.
- 시작 전: 앱/커밋, OS, 화면 크기, 모델 캐시 유무, 실행 장치, 자료 파일 수와
  SHA256 목록, 참가자 경험, 안내문 버전을 기록한다. 모델 설치 시간은 따로
  적되 처음 실행 총시간에서 숨기지 않는다.
- 과제: 새 프로젝트 → 폴더 선택 → 작업/분할 확인 → 초안 또는 직접 라벨링 →
  사람 검토·명시 채택 → 추천 학습 → 평가 결과 확인 → 첫 검사 흐름 저장.
- 측정: 화면 녹화 동의 후 프로젝트 만들기부터 첫 검사 흐름 저장까지 잰다.
  필수 클릭·터치 횟수, 키 입력/단축키, 모델 대기시간, 오류/도움 요청을 별도로
  기록한다. 실패 시 종료하지 말고 중단 위치·원인과 재개까지 남긴다.
- 이 과제의 개발 목표: 전체 경과 30분 이내, 필수 클릭 40회 이하. 아직 사람 측정으로
  달성을 확인하지 않았으며 다른 자료·사용자·장비의 보편 기준으로 쓰지 않는다. 필수 정답 검토와 채택을
  생략해 수치를 맞추지 않는다. 미달 화면은 녹화의 시각과 함께 수정 목록에 넣는다.

장당 시간은 같은 종류·난이도의 이미지를 두 묶음으로 나눠 직접 그리기와
초안 검토/수정/채택을 번갈아 수행해 비교한다. 초안 계산·로딩과 사람 검토·수정
시간을 모두 포함하고, 이미 답을 본 효과를 피하도록 순서를 바꾼다. 빈 후보,
잘못된 후보, 거절·되돌림 시간도 포함한다. 수치가 나올 때까지 결과는 미측정이다.

## 현장 품질 확인

사용자가 대표 OK/NG 이미지와 확정 정답의 위치를 지정하고, 결함 정의·클래스와
허용 기준을 정한다. 비밀 자료를 외부로 보내지 않고 로컬 별도 시험 공간에서
동일 이미지·동일 정답·고정 모델/SHA·기준값으로 평가와 검사 결정을 비교한다.

| 이미지/정답 출처 | 실제 결함·클래스 | 모델/기준값 | 예측 | 놓친 불량/잘못 잡은 정상 | 사람 판정·이유 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

분류는 이미지별 오류, 검출은 결함별 놓침·오검출과 상자 IoU, 분할은 정답 마스크
IoU 및 누락 영역을 저장한다. 수치와 대표 실패 이미지를 함께 검토한다. 모델
자체 confidence/예측 IoU를 정답 대비 점수로 쓰지 않는다. 합성 사각형 통과나
5장 검사 완료는 현장 품질 승인이 아니다. 정답 확인·품질 수용·운영 적용은
담당자가 기록하며, 개발 검사 성공으로 이를 대신하지 않는다.

## 실제 계정 확인

현재 공개 도우미는 데스크톱 앱의 ChatGPT 계정 연결을 통한 텍스트 질문을
지원한다. API 키 입력과 이미지 전송은 이 공개 흐름에 포함되지 않는다.

사용자가 전송·보관 안내와 Sign in with ChatGPT 약관을 확인한 뒤
`Continue with ChatGPT`로 열린 시스템 브라우저에서 직접 로그인한다. 필요한 플랜
사용 권한과 앱의 플랜 사용 안내를 확인하고, 모델 목록에서 사용할 모델을 직접 고른다.
로그인·모델 목록·선택·질문 완료를 각각 기록하며, 다른 앱의 토큰이나 쿠키를 가져오지 않는다.

2026-10-24 사용자 참여 기록에서 공식 로그인·플랜 권한·모델 목록/선택·재시작 후
유지가 확인됐다. 별도 승인된 이미지 없는 텍스트 세 시도 중 앞의 두 번은
`bad_response`, 마지막 `dd6651fa`는 텍스트 8자·도구 호출 0회로 정상 완료됐다
([상세 기록](2026-10-24-remaining-validation.md)). 이 성공은 해당 빌드의 텍스트 1회
완료 근거다. 세 승인과 attempt marker는 모두 사용됐으며 실패 기록도 보존한다.
현재 추가 실제 요청은 승인되지 않았다.

도구 호출·실제 토큰 갱신·한도 중단/회복·로그아웃/서비스 권한 철회·다른 OS와
최종 설치본의 계정 동작은 별도 확인이 남는다. 로컬 연결 삭제와 서비스 쪽 철회도
구분한다. 후속 시험은 사용자가 항목·선택 계정/모델·전송 내용·허용 요청 횟수와
플랜 사용을 정한 범위에서 진행한다. 결과가 불확실하거나 실패한 요청도 그 횟수에
포함하며 자동 재시도하지 않는다.

한 번의 연결 점검은 별도 준비 도구의 `context: {}`, `tools: []`, 이미지 없는 경로로
제한한다. 일반 UI 질문은 앱 도구를 제안하고 여러 공급자 요청이 이어질 수 있어
한 번의 연결 점검과 같은 시험으로 세지 않는다. 로컬 준비·상태 조회·가짜 공급자
시험은 실제 계정 요청 완료를 대신하지 않는다. 자격 증명·인증 URL·계정 식별자와
질문/응답 원문은 검증 기록에 넣지 않는다.

2026-10-24 사용자가 로컬·외장 자료 사용을 지정한 뒤 고정한 실제 이미지와
엔진 실행 결과는 [실제 이미지 진단](2026-10-24-real-image-foundation-diagnostic.md)에
기록했다. 기존 정답의 사람 재확정·처음 사용자 시간·현장 품질 승인은 별도로 남는다.

합성 예제·과거 성공을 새 현장/설치본의 결과로 복사하지 않는다.
