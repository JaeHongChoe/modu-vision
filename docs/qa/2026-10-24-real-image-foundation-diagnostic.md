# 실제 로컬 이미지: 첫 초안 모델 진단 (2026-10-24)

사용자가 외장·로컬 자료를 찾아 사용하도록 지정하여, 새 공개 자료 다운로드 대신
로컬 미코 이미지와 기존 LabelMe/CSV 정답을 별도 시험 공간으로 복사했다.
원본·확정 라벨·사용 중 프로젝트에는 쓰지 않았고, 학습·외부 전송·초안 채택도 하지 않았다.
이번 근거는 **실제 이미지에 대한 앱 엔진 함수 실행**이다. 새 실제 앱 UI 시험이나
사람의 정답 재확정·처음 사용자 시간 측정·현장 품질 승인이 아니다.

## 고정한 자료와 조건

- 영역 자료: 기존 113쌍 중 Crack 6장/Bow 6장, LabelMe 12쌍과 폴리곤 49개.
  한 이미지에 37개가 있어 인스턴스 수 기준 결과가 그 이미지에 크게 좌우된다.
- 이미지 수준 자료: 기존 CSV 438행의 원본 중 NG 12장/OK 12장. `merged/`의
  원본+기존 추론 색칠 비교 그림은 제외하고 대응 `*_orig.jpg`만 복사했다.
- 클래스별 파일명 정렬 후 동일 간격의 중앙 순위를 선택했다. 모델 결과로 고르지 않았다.
  36장 중 고유 SHA는 35개이며, 두 묶음 사이 중복 1쌍이 있다. 독립 학습/시험 분할이 아니다.
- 복사한 이미지 36개/JSON 12개의 SHA와 선택 원본·JSON·원본 CSV 49파일의
  전후 SHA/크기/mtime을 확인했다. 추론 뒤에도 입력·원본 SHA가 같았다.
- 앱 엔진 소스는 `acfa347499f8073a9136dcf0cd18c87ce338c52b`의
  `grounded_candidates`와 `foundation_candidates`를 그대로 사용했다. CPU,
  PyTorch 2.9.1/transformers 4.57.6, Hugging Face 오프라인 모드였다.
- 기존 고정 모델 SAM2 `de431c4…`/Grounding DINO `a2bb814…`의 공식 가중치
  SHA 일치를 준비 검사에서 확인했다. 새 모델을 받거나 재학습하지 않았다.

전체 출처 경로·파일별 지문·예측·선택 정답/예측 마스크는 비공개 로컬 근거에 보관했다.
이미지·정답·개인 경로는 이 저장소에 넣지 않았다.

## 실제 결과

| 경로 | 고정 조건 | 기존 정답과 비교한 결과 |
| --- | --- | --- |
| 문구 → 검출 초안 | 모든 이미지에 `crack . defect .`, box 0.30/text 0.25. 클래스 비구분, 점수순 일대일 box IoU≥0.5 매칭 | 영역 12장: TP 0, FP 18, FN 49. 정답 상자를 IoU 0.5 이상으로 잡은 후보 0개 |
| 문구 후보 유무를 NG로 보는 진단용 대리 규칙 | 위 문구/기준값 유지. 학습된 분류기나 운영 판정 규칙이 아님 | NG 12장 모두 후보가 있었지만 OK 12장에도 모두 후보가 있었음. 미탐 0/12, 정상 과검 12/12로 정상·불량을 구분하지 못함 |
| 정답 위치를 알려 준 SAM2 클릭 보조 | 각 이미지에서 가장 큰 정답 폴리곤의 최대 내부거리 픽셀에 양성점 1개. 정답 상자/음성점 없음. 후보 기준 0.5 | 선택한 인스턴스와 원본 해상도 mask IoU 평균 0.2788, IoU≥0.5는 4/12장. 3장은 앱 필터 후 후보 0개여서 IoU 0으로 집계 |

SAM2의 점은 기존 정답으로 계산한 **정답 보조 입력**이다. 자동 결함 탐지 성능이나
사람의 클릭 속도를 뜻하지 않는다. `confidence`/모델 자체 예측 IoU와 위의 정답 대비
mask IoU는 별도 값이다. 후보 0개의 상세 원인(점수·빈 마스크·퇴화 형상)은
이 경로의 반환 결과만으로 분리하지 못했다.

총 엔진 경과는 약 81초였다(첫 모델 로딩 포함, 중복 이미지 예측 1회 재사용).
사람의 검토·수정·채택을 포함한 장당 시간이나 30분/40회 목표 측정이 아니다.
자료 준비 스크립트에서 `annotation:null` 처리 누락으로 첫 사전 검사가 멈췄고,
모델 실행 전 이를 고친 뒤 위 36장 실행을 한 번 완료했다. 실패 로그와 빈 출력 폴더도 보관했다.

## 판정과 다음 단계

이 고정 모델/문구 조합을 해당 이미지의 검사 모델로 승인할 근거는 없다.
문구 초안은 사람 검토를 전제로 유지하며, 후보 유무로 OK/NG를 자동 결정하면 안 된다.
실제 결함 정의와 기존 라벨의 완전성을 담당자가 확인한 뒤, 제품/로트 단위로 분리한
훈련·검증·시험 묶음과 적합한 결함 모델을 준비해야 한다. 같은 36장의 문구/기준값을
반복 조정해서 현장 성능으로 보고하지 않는다. 공개 MVTec 대체 다운로드는 이번에는 필요하지 않았다.
