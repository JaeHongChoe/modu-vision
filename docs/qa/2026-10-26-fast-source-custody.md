# 현재 소스 등록과 OCR 종료 검증 보완

PR12 `6fb4386c`의 fast40238773237, PR14 `ea8c99ea`의 fast40238970308은 각각 8/11 job 성공·CPU1/2/5 실패였습니다. 같은 네 소스 코호트 시험과 OCR 파일 보존 시험이 실패했고, 이전 실패를 아래 로컬 결과로 덮지 않습니다.

## 수정

그래프 스키마 분리로 엔진은 151555바이트에서 149170바이트로 바뀌고 `flowchart_schema.py`가 생겼지만 현재 코호트는 이전 엔진을 요구했습니다. 기존 네 코호트와 결합된 profile·선택 순서를 보존하고, 새 엔진과 스키마를 함께 고정하는 별도 일곱 파일 코호트를 추가했습니다. 정확한 등록 관찰자 검증도 새 코호트에 적용합니다. 파일 변조·누락·심볼릭 링크와 불완전/혼합 선언은 거절하며, 원래 영수증·실행 소스·모델·이미지·승인 기록은 변경하지 않습니다.

OCR 시험은 영수증 게시를 실행 종료로 간주한 뒤 결과 파일을 변조했습니다. 원래 SOURCE 종료 검증은 게시 후에도 결과 바이트를 읽으므로 정당한 복구 전이가 시험의 마지막 동등 비교와 경합했습니다. 시험에서만 원래 `execute_cpu`의 정상 반환 뒤 정확한 controller/nonce/request/receipt 결합을 관측하고, 기존 공유 50초 안에서 이 종료를 확인한 뒤 변조합니다. 기존 28개 단언과 파일 동등 비교는 모두 남아 있고 체크섬 거절 이유까지 확인합니다. 제품 종료 코드·상한·재시도·원본 보호는 변경하지 않았습니다.

F064 현재 시험도 새 엔진과 스키마를 함께 고정합니다. 실제 브라우저 확인 중 초기화 요청의 순서 가정 두 가지가 드러났습니다. 프로젝트를 확인한 뒤 보낸 요청은 정확한 scoped header로 검사하며, 저장된 5단계는 1단계 데이터 컴포넌트를 마운트하지 않습니다. 직접 복원된 플로우·저장 상태를 먼저 확인한 다음 일반 1단계→5단계 탐색을 명시해 기존 네 경로와 실제 전체 응답을 계속 검증합니다. 허용 경로·프로젝트/컨텍스트·이벤트 시작 기준 10초·바이트/파일 핸들·읽기/쓰기 종료·저장 그래프 단언을 유지했습니다. 과거 GUI 선언 두 행의 현재 시험 SHA/이유만 갱신했으며, 원래 영수증·실행 SHA·기록된 시험 SHA·보존 조상은 그대로입니다.

## 로컬 관측

- 원래 코호트 실패 4건을 재현했습니다. 새 코호트 시험은 구현 전 7 failed/13 passed, 구현 후 **20 passed**입니다. 관련 공개 source/factory/observer/resources/rotation/schema 묶음은 별도 호환 QA 환경에서 **178 passed**입니다. 원래 네 소스 묶음의 정확 바이트 검증도 별도 읽기로 확인했습니다.
- OCR의 원래 경합은 실제 종료 읽기를 통제한 수정 전 실행에서 같은 8→9 복구/체크섬 이유로 재현했습니다. 수정 후 지연 종료 대조가 통과했고, 실제 실행 파일 전체는 **65 passed**입니다. 원래 CPU threads1/deadline30000 조건과 종료 후 소유 프로세스 부재를 확인했습니다.
- 원래 F064 공개 브라우저 전체 사례는 최종 시험 바이트에서 **1 passed(41.0초)**입니다. 세 저장/재열기 셀, 네 문서 전환의 네 경로, 직접 복원 후 데이터 화면 탐색, 전체 읽기/쓰기 종료와 파일 핸들 닫힘을 확인했습니다. 앞선 두 초기화 단언 실패와 trace도 보존했습니다. Electron/설치 시험은 재실행하지 않았습니다.
- GUI 역사/실행/작업 근거와 그래프 계약 묶음 **85 passed**. E2E 타입과 서비스/작업 근거 게이트 통과. 검증 시나리오 1014/pending435/accepted feature0 유지. 서로 겹칠 수 있는 별도 실행은 합산하지 않습니다.

로컬 기본 FastAPI0.108에서는 관련 묶음 169 passed/9 failed였으며, 모두 기존 `APIRouter.app` 접근에서 실패했습니다. 이를 보존하고 기존 격리 FastAPI0.142.2/Starlette1.7.0 QA 환경에서 같은 묶음을 검증했습니다. Pydantic/ML 패키지는 상속하므로 전체 CI 잠금 환경과 같다는 뜻은 아닙니다. 기존 python_multipart/Node 색상 경고와 프로브 작성 오류도 기록했습니다.

현재 로컬 결과는 새 게시 head의 hosted fast/full 성공을 대신하지 않습니다. 과거 SOURCE6 외부 fixture와 실제 현재 소스를 섞는 비공개 replay는 새 일곱 파일 코호트의 수락 근거로 사용하지 않았습니다. 모델/현장 품질, 실제 계정·유료 요청, GPU, 대상 OS/설치·서명·배포, 사람 수용이나 새 역사적 GUI 실행 크레딧을 주장하지 않습니다.
