# 학습형 정방향 회전과 좌표

이 작업대는 이미지별 반시계 보정각을 명시적으로 저장하고, train으로 학습해 val로 후보를 선택하며 test의 원형 각도 오차를 평가합니다. 방향은360°이므로0°와180°가 다릅니다. 회전 상자의 축은180° 주기이며 앞뒤 정방향의 정답을 대신하지 않습니다. 회전 대칭 제품의 방향 품질은 실제 정답과 별도 검토가 필요합니다.

플로우는 지정 각도의 회전, 회전 검출 상자를 이용한 기하 정렬, 학습 후보를 이용한 정방향 보정을 지원합니다. 기준 이미지 템플릿 정합은 지원하지 않습니다. 학습 후보 연결은 해당 모델 ID를 보존하며 새 노드의 연결선을 별도로 지정합니다.

## 좌표 계약

- `transform`: 원본 픽셀 중심에서 정렬 이미지 픽셀 중심으로 가는3×3 행렬.
- `inverse_transform`: 정렬 픽셀 중심에서 원본으로 가는 역행렬.
- `alignment_recipe`: learned_direction, 반시계360° 보정, [-180,180] 범위와 bilinear 보간 및 두 행렬의 방향.
- ROI·box·문자 polygon은 반열린 영역 경계 좌표입니다. 픽셀 중심 행렬을 그대로 경계에 곱하지 않고 경계→중심(-0.5)→중심 변환→경계(+0.5)로 복원합니다. 마스크 raster는 중심 행렬과 nearest 보간으로 복원합니다.
- 정렬은 전체 원본 영역을 보존하도록 출력 canvas를 확장합니다. 원본 이미지를 수정하지 않습니다.

앱 예측과 TorchScript 패키지는 같은 픽셀·각도·양방향 좌표를 사용합니다. 방향 벡터가 정의되지 않은 모델은 추론과 평가가 모두 실패합니다. 패키지의 파일 checksum 또는 원본/정답 provenance가 달라지면 거절합니다.

## 확인한 범위

Task101은 실제 Chrome와 macOS 개발 Electron에서16개 자체 생성 이미지의 라벨 입력→준비→20회 CPU 학습→4개 시험 이미지 평가→원본 정렬→패키지 별도 실행→재열기→모델 노드 연결을 확인했습니다. 원본/준비 이미지, 완료 작업·체크포인트·평가 기록·패키지 hash를 다시 읽었습니다. 별도 제어된 모델의 ROI/상자/마스크/문자 좌표 및 전체 플로우 패키지와 C++ 실행 계약도 확인했습니다.

합성 방향 예제의 MAE는9.9344°였으며 대표 제품 품질·승인·GPU 또는 설치된 현장 장치 합격을 뜻하지 않습니다. Windows 테스트는 사용자 요청으로 제외했습니다. 구체적 검증 기록은 통합 근거 문서의 Task101에 있습니다.
