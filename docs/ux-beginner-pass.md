# 초보 사용자 화면 정비 (2026-10-19)

처음 쓰는 사람이 설치 뒤 결과까지 가는 길을 쉽게 하기 위한 화면·접근성 정비입니다. 기능 계약(API, 검증 규칙, 저장 형식)은 바꾸지 않았습니다.

## 바뀐 것

| 영역 | 전 | 후 |
| --- | --- | --- |
| 상단 바 | `Compute: This computer`, `RECIPE:`, `METAL GPU MPS / HW ACCEL`, `PORT:57944` (10~11px) | `실행 위치: 이 컴퓨터`, `검사 종류`, 6단계 이름 (14px). 포트·장치·가속 정보는 **기술 상세** 버튼을 켰을 때만 |
| 단계 표시 | 색으로만 구분 | 현재 단계에 `aria-current="step"`, 좁은 창에서는 줄바꿈 (잘리지 않음) |
| 글자 크기 | 7~11px 535곳, 12px 581곳 | 12px 하한, `text-xs`는 13px, 제목은 본문보다 큼 |
| 대비 | `slate-500` 보조 글자 3.4~4.1:1 | 모든 배경에서 4.5:1 이상 |
| 글꼴·언어 | 한글 글꼴 미지정, `lang="en"` | 한글 글꼴 지정, `lang="ko"` |
| 확대 | 없음 | 보기 메뉴와 Ctrl/Cmd `+` `-` `0`, 설정은 다음 실행에도 유지 |
| 데이터 단계 | 32/32 균형 데이터에 "극심한 클래스 불균형 (ERR_003)" | 실제 20:1 초과일 때만 |
| 분할 계산기 | 예상 80/10/10을 보여 주고 실제 적용 40/12/12는 다른 곳 | 저장된 분할을 먼저 보여 주고, 바꾸기 시작하면 예상으로 전환. 학습·검증·시험 표기 |
| 처음 시작 안내 | 2번 항목에서 3단계로 먼저 이동 | 프로젝트 → 데이터 → 학습 순서. 결과 버튼은 검사 이력 위치로 이동 |
| 검사 결과 | 저장 버전·그래프·체크포인트 해시가 본문에 | 기술 상세를 켰을 때만. 평소에는 "저장한 검사 플로우 v…로 검사했습니다" |
| 하단 안내 | 성공 뒤에도 "부족한 입력" | "다음 할 일" |
| 운영자 검사 | 버튼이 모두 같은 회색, "승인 기록 … 확인 필요" | 검사 시작이 주요 버튼, 승인이 왜 필요한지 한 문장 |
| 아이콘 버튼 | 이름 없음 또는 영어 툴팁 | 한국어 이름 (갤러리 이전·다음, 클래스 추가·취소, 마스크 보이기, 라벨 삭제, 확대·축소 등) |
| 오류 대화상자 | `role` 없음, `[진단 원인 설명]` | `role="dialog"`, Esc로 닫기, Tab이 밖으로 나가지 않음, "무슨 일이 있었나요 / 원인으로 보이는 것 / 이렇게 해 보세요" |

## 확인 방법

- 단위 검사: `node --test src/renderer/components/wizard/WizardHeader.beginner.test.cjs src/renderer/styles/typography.test.cjs src/renderer/components/dataset/splitCalibrator.test.cjs src/renderer/components/onboarding/firstRunGuide.test.cjs src/renderer/components/common/accessibilityLabels.test.cjs`
- 전체: `npm run typecheck`, `npm run test:renderer` (1,457개 통과)
- 실제 화면: 예제 프로젝트를 만든 뒤 1단계에서 불균형 경고가 없고 분할이 "저장됨"으로 보이는지, "검사 결과 보기"가 검사 이력에 멈추는지, 상단 바에 포트·장치가 보이지 않는지 확인합니다. 1000px 너비에서 6단계가 모두 보여야 합니다.

## 2차 (같은 날)

| 영역 | 내용 |
| --- | --- |
| 밝은 테마 | `scripts/generate_light_theme.cjs`가 렌더러에 쓰인 색 클래스 전부를 읽어 `styles/theme-light.css`를 만듭니다(어두운 면은 밝은 면으로, 밝은 글자는 어두운 글자로, 색 글자는 같은 색상에서 AA 대비까지 어둡게). 상단 바의 "밝은 화면 / 어두운 화면" 버튼, 기본값은 OS 설정을 따름. 테스트가 생성 결과의 최신 여부, 10회 이상 쓰인 클래스의 커버리지, 모든 글자색의 대비를 보증합니다. |
| 예제 흐름 | 저장한 플로우를 시험 이미지로 평가하는 단계가 들어가 6단계의 "전체 플로우 평가 필요"가 사라집니다. 이를 위해 플로우 평가가 train/val/test **폴더 분할**도 명시적 분할로 받아들입니다(저장 분할 파일이 있으면 그것이 우선). |
| 해시 노출 | 플로우 식별 카드와 편집기 머리글의 버전은 `v`+8자로, 그래프 해시·모델 작업 ID는 기술 상세에서만. 6단계 안내 문구에서 "승인 revision" 제거. |
| 오류 문구 | 프로젝트·데이터·예제 경로의 백엔드 거절 문구 약 45개를 한국어로. `backend/tests/test_beginner_errors_korean.py`가 영어 리터럴이 다시 들어오지 않게 지킵니다. |

## 3차 (같은 날)

| 영역 | 내용 |
| --- | --- |
| 한글 글꼴 | Pretendard Std 1.3.9 가변 글꼴(OFL 1.1)을 `public/fonts/`에 동봉. 라이선스 전문은 같은 폴더와 `THIRD_PARTY_NOTICES.md`에. OS에 같은 글꼴이 있으면 그것을 먼저 씁니다. |
| 3단계 학습 | 레시피 카드가 "빠른 시험 학습 / 정밀 후보 학습"처럼 읽히고, 상태·회차·손실 그래프·툴팁이 한국어. 장치 사용량 패널은 기술 상세를 켰을 때만. 학습이 끝나면 "학습이 끝났습니다 … 결과 평가하기 (4단계)" 버튼이 나타나고 하단 안내도 4단계를 가리킵니다. |
| 4단계 평가 | 맨 위에 한 줄 요약("시험 이미지 12장 중 11장 맞음 · 미검(놓친 결함) 1 · 과검(정상을 결함으로) 0"), 지표 이름(정확도·정밀도·재현율·F1), 판정 배지와 두 화면 라벨(원본 이미지 / 결함 열지도, 정답 / 판정)이 한국어. "고정 테스트 코호트"는 "시험 이미지 묶음". |
| 6단계 | 실제 이미지 일괄 검사가 단일 모델 시험보다 위에 옵니다. |
| 1·2단계 | 데이터 화면의 "Pixel Pitch: Not calibrated"는 "픽셀당 길이: 미보정", "클래스별 계측 분포"는 "클래스별 이미지 수". 라벨링 화면의 라벨 세트·클래스·측정 정보·라벨 목록·위치/크기/보기 읽기값·빈 목록 안내("이 이미지에는 라벨이 없습니다")·쪽 번호가 한국어. 저장·정상 표시 버튼(Save Changes / Mark as Normal)은 e2e 영수증 다수가 이름으로 읽어 이번에는 두었습니다. |
| 단계 배너 | STEP 제목이 "모델 학습 / 결과 평가 (미검·과검 확인) / 검사 플로우 만들기 / 검사 실행 & 내보내기". 대괄호 영어 코드는 기술 상세에서만. |
| 오류 문구 | 학습·평가·플로우·검사·모델 비교 경로의 백엔드 거절 문구를 한국어로(다음 할 일 포함). `test_beginner_errors_korean.py`의 감시 대상 라우트가 8개로 늘었습니다. |
| 공개 PR 검사 | 증거 게이트가 요구하는 소스 해시 재바인딩과 이력 선언(바뀐 e2e 스펙 10건)을 갱신했습니다. 새 GUI 실행을 주장하지 않습니다. |

확인한 화면: 예제 프로젝트를 브라우저 모드 앱에서 끝까지 실행한 뒤 3·4·6단계를 눈으로 확인. e2e `service-s2-01`, `service-s0-08`(크롬 채널) 통과. `npm run typecheck`, `npm run test:renderer`(1,465개) 통과.

## 남은 것

- 데이터·라벨링(1~2단계) 화면의 세부 문구(진단 기준 입력, 고급 설정)는 아직 전문 용어가 남아 있습니다.
- 바뀐 e2e 스펙의 GUI 영수증은 이력 선언으로만 유지됩니다. 새 영수증은 승인된 GPU 서버의 실제 데스크톱 앱 검증에서 받아야 합니다.
