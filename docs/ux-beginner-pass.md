# 초보 사용자 화면 정비 (2026-10-19)

처음 쓰는 사람이 설치 뒤 결과까지 가는 길을 쉽게 하기 위한 화면·접근성 정비입니다. 기능 계약(API, 검증 규칙, 저장 형식)은 바꾸지 않았습니다.

## 바뀐 것

| 영역 | 전 | 후 |
| --- | --- | --- |
| 상단 바 | `Compute: This computer`, `RECIPE:`, `METAL GPU MPS / HW ACCEL`, `PORT:57944` (10~11px) | `실행 위치: 이 컴퓨터`, `검사 종류`, 6단계 이름 (14px). 포트·장치·가속 정보는 **기술 상세** 버튼을 켰을 때만 |
| 단계 표시 | 색으로만 구분 | 현재 단계에 `aria-current="step"`, 좁은 창에서는 줄바꿈 (잘리지 않음) |
| 글자 크기 | 7~11px 535곳, 12px 581곳 | 12px 하한, `text-xs`는 13px, 제목은 본문보다 큼 |
| 대비 | `slate-500` 보조 글자 3.4~4.1:1 | 모든 배경에서 4.5:1 이상 |
| 글꼴·언어 | 한글 글꼴 미지정, `lang="en"` | 한글 글꼴 지정, `lang="ko"` |
| 확대 | 없음 | 보기 메뉴와 Ctrl/Cmd `+` `-` `0`, 설정은 다음 실행에도 유지 |
| 데이터 단계 | 32/32 균형 데이터에 "극심한 클래스 불균형 (ERR_003)" | 실제 20:1 초과일 때만 |
| 분할 계산기 | 예상 80/10/10을 보여 주고 실제 적용 40/12/12는 다른 곳 | 저장된 분할을 먼저 보여 주고, 바꾸기 시작하면 예상으로 전환. 학습·검증·시험 표기 |
| 처음 시작 안내 | 2번 항목에서 3단계로 먼저 이동 | 프로젝트 → 데이터 → 학습 순서. 결과 버튼은 검사 이력 위치로 이동 |
| 검사 결과 | 저장 버전·그래프·체크포인트 해시가 본문에 | 기술 상세를 켰을 때만. 평소에는 "저장한 검사 플로우 v…로 검사했습니다" |
| 하단 안내 | 성공 뒤에도 "부족한 입력" | "다음 할 일" |
| 운영자 검사 | 버튼이 모두 같은 회색, "승인 기록 … 확인 필요" | 검사 시작이 주요 버튼, 승인이 왜 필요한지 한 문장 |
| 아이콘 버튼 | 이름 없음 또는 영어 툴팁 | 한국어 이름 (갤러리 이전·다음, 클래스 추가·취소, 마스크 보이기, 라벨 삭제, 확대·축소 등) |
| 오류 대화상자 | `role` 없음, `[진단 원인 설명]` | `role="dialog"`, Esc로 닫기, Tab이 밖으로 나가지 않음, "무슨 일이 있었나요 / 원인으로 보이는 것 / 이렇게 해 보세요" |

## 확인 방법

- 단위 검사: `node --test src/renderer/components/wizard/WizardHeader.beginner.test.cjs src/renderer/styles/typography.test.cjs src/renderer/components/dataset/splitCalibrator.test.cjs src/renderer/components/onboarding/firstRunGuide.test.cjs src/renderer/components/common/accessibilityLabels.test.cjs`
- 전체: `npm run typecheck`, `npm run test:renderer` (1,457개 통과)
- 실제 화면: 예제 프로젝트를 만든 뒤 1단계에서 불균형 경고가 없고 분할이 "저장됨"으로 보이는지, "검사 결과 보기"가 검사 이력에 멈추는지, 상단 바에 포트·장치가 보이지 않는지 확인합니다. 1000px 너비에서 6단계가 모두 보여야 합니다.

## 남은 것

- 밝은 테마: 색 토큰이 `index.css`, `styles/design-tokens.css`, `tailwind.config.js` 세 곳에 있어 먼저 한 곳으로 모아야 합니다.
- 한글 글꼴 동봉(Pretendard 등): 지금은 OS 글꼴을 씁니다.
- 예제가 끝난 뒤 6단계의 "다음 할 일: 전체 플로우 평가"는 맞는 안내이지만, 예제 흐름에 플로우 평가를 넣으면 바로 "준비됨"이 됩니다.
- 백엔드 오류 문구의 한국어화는 경로별로 나눠 진행합니다.
